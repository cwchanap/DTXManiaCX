# HPA-803 — Declarative settings and SQLite-only configuration

**Linear:** https://linear.app/cwchanap/issue/HPA-803  
**Implementation:** [one-PR plan](../superpowers/plans/2026-11-27-hpa-803-implementation-plan.md)  
**Baseline:** main `e7204eba135e0b1b201135e2a5027b6d94fa0539` (2026-11-27). HPA-797 and HPA-802 are complete.  
**Revision:** addresses [review 6091001518](https://github.com/cwchanap/DTXManiaCX/pull/256#pullrequestreview-6091001518) and [review 6095110317](https://github.com/cwchanap/DTXManiaCX/pull/256#pullrequestreview-6095110317).  
**Status:** design only; implementation, builds, tests and MCP acceptance have not been executed.

## Objective and boundaries

Define each live scalar setting's persistence, normalization and UI metadata in one typed descriptor table. Keep typed `ConfigData` reads in gameplay and preserve the Config screen and Quick Settings popup. Remove Config.ini bootstrap throughout the game, E2E harness and recorder.

The reviewed design refines the ticket's literal “one-place change” target: a new ordinary setting has a typed property/default in `ConfigData`, one descriptor definition registered in `ConfigSettings.All`, and one descriptor reference in each screen that displays it. The behavioral definition is shared; screen placement remains explicit. No new parser arm, save entry, manager/interface setter or copied UI metadata is needed. Do not claim this is a single-property edit.

One PR, maximum three engineer days including acceptance. Use current .NET 10, MonoGame, SQLite, the unified unit project and existing MCP. No new setting, asset, generator, runtime reflection catalog, DI framework, event bus, input redesign, nullable sweep or schema bump. No compatibility migration for obsolete INI or DB rows. Retain canonical keys for live settings and ConfigEntries v1; remove unused settings and legacy aliases.

## 1. Typed settings table

Use one `ConfigSettings` table for the 27 live scalars remaining after the five agreed deletions. Each scalar has a typed descriptor containing:

- Canonical key using `nameof(ConfigData.Property)`, typed get/set delegates and a codec selected by type.
- One pure `Normalize` delegate, defaulting to identity.
- Optional UI metadata: label, base description, integer bounds/step/formatter, boolean formatter or existing enum option table.

`ConfigSettings.All` and its ordinal key lookup are internal and use a small internal common descriptor interface (`IScalarSetting`) for load/save. Distinguish persistence from ordinary editing at the type boundary:

| Descriptor | Use |
| --- | --- |
| Public sealed immutable `ConfigSetting<T>`, with internal construction | The 19 ordinary scalars whose named setters are removed below; these handles can be passed to `IConfigManager.Set<T>` and the item factory. |
| Separate internal persistence descriptor, not assignable to `ConfigSetting<T>` | SkinPath, SystemSkinRoot, UseBoxDefSkin, ScreenWidth, ScreenHeight, EnableGameApi, GameApiPort and GameApiKey. These eight participate in the same load/save catalog but cannot be supplied to the generic edit API. |

Share codecs, normalization and descriptor mechanics across both forms. This is one catalog with two capabilities, not parallel registries. Making the eight fields merely internal while retaining the same editable handle type would still allow game/UI code in the same assembly to bypass `SetSkinPath` or half-update resolution. Keep those operations behind their existing manager APIs. Direct ConfigData writes remain possible by design; this boundary constrains the new manager edit API. No production reflection or extensible settings framework is needed.

Keep default values in `ConfigData` initializers. Read a fresh default instance when default metadata is needed, so AppPaths-dependent values are not captured across app-data roots. Reuse `ScrollSpeedRange`, `PlaySpeedRange`, `PitchRange`, `RiskyRange`, the latency formatter and Cymbal Group's Shared/Separate formatter. Expose the existing Lane Display and Note Display `OptionTable` objects internally and add a small `EnumOptionTable<GaugeDamageLevel>` with the current Low/Normal/High labels and order, so all three enum dropdowns use one factory path. An undefined damage level normalizes to `GaugeDamageLevel.Normal`, not the zero-valued Low; UI option order must not determine the default. Keep enum-name persistence parsing separate from label mapping.

Screen/category placement belongs to each UI's ordered list of descriptor references and special controls. Descriptors do not carry category/order numbers, and there is no order-gap merge.

### Normalization and codecs

| Concern | Rule |
| --- | --- |
| Load | Parse a recognized scalar, normalize and assign it; unparseable bool/int/enum input leaves the initialized/current value unchanged. Collection keys use their dedicated parser. |
| Explicit edit | Normalize, compare old/new, assign on change, mark dirty and dispatch the existing edit notification. |
| Save | Serialize `Format(Normalize(Get(config)))` for every descriptor; serialization does not mutate live values or publish edit events. |
| Values | Preserve accepted bool spellings, invariant integers, case-insensitive enum names and rejection of numeric enum strings. Undefined programmatic enum values normalize to the existing default. Strings remain strings, with null coalesced for NOT NULL storage. |
| Bounds | Keep UI bounds separate from storage normalization. Audio latency accepts any nonnegative stored/programmatic value, while the UI remains 0–500 in steps of 10. Do not add dimension/API-port clamps. |

Normalization on save now also covers scroll speed and audio latency. This is an intentional consistency change for direct property writes. Path resolution, managed-root correction, the relocatable Default skin token and API-key provisioning remain manager lifecycle responsibilities; a scalar normalizer must not trim every string or replace those operations.

## 2. Manager ownership and deliberate deletions

Expose `Set<T>(ConfigSetting<T> setting, T value)` on `IConfigManager`/`ConfigManager` for the 19 ordinary scalars only. Use the typed handle at the mutation boundary. The eight persistence-only descriptors cannot be supplied to this API. Keep `AdjustScrollSpeed` as a thin call to it. Direct property assignment remains in-memory only.

Delete the config-specific named scalar setters after migrating their callers: `SetScrollSpeed`, `SetPlaySpeedPercent`, `SetPitchSemitones`, `SetMetronome`, `SetRandomSelectFromSubBox`, `SetNoFail`, `SetRisky`, `SetDamageLevel`, `SetAutoAddGauge`, `SetLaneDisplayMode`, `SetNoteDisplayStyle`, `SetShowJudgementLine`, `SetEnableLaneFlush`, `SetShowCombo`, `SetShowHitTimingFeedback`, `SetShareCymbalLanes`, `SetAudioLatency`, `SetFullscreen` and `SetVSync`. These are currently consumed by ConfigStage and QuickSettingsPopup. Preserve unrelated graphics and note-renderer methods with similar names.

`ScrollSpeedChanged` remains the only scalar event. One explicit case in the common mutation path raises it on a changed scroll-speed edit with old/new values, preserving subscriber isolation. Load does not publish it, matching the interface contract and startup lifecycle. Equal normalized scalar edits do not mark dirty; this intentionally removes redundant saves from several old setters. Collection events and `BaseConfigItem.ValueChanged` keep their own contracts.

| Delete | Preserve |
| --- | --- |
| `ResetToDefaults` and tests of that unused manager API | Fresh construction defaults; live FFmpeg “reset speed/pitch to default” behavior and key-binding defaults |
| `MasterVolume`, `BGMVolume`, `SEVolume`, `DTXManiaVersion`, `LastUsedSkin`, their config rows/tests and obsolete volume TODO comments | Actual audio routing and NX score-import metadata with similar names |
| INI importer/path API, DTXPath migration, RandomFromSubBox alias and bare AutoPlay compatibility branch | Theme.ini/SkinConfig.ini processing and NX score import |
| INI bootstrap artifact copies | Existing chart, audio, logs, state and screenshot diagnostics |

Keep `SetResolution`, `SetSkinPath` with normalized comparison, `SetSongRoots`, key/unbound/system bindings, MIDI thresholds and AutoPlay operations. Do not split compound edits into separate observable transactions. Dynamic row families stay out of the scalar table: ordered SongRoot.N, Key/Pad/MIDI mappings, unbound markers, SystemKey.*, MidiVelocity.N and sparse AutoPlay.N. Preserve current validation, order and conflict handling.

Keep the load-before-save guard, existing DB/schema errors, path-correction persistence and retry, deferred flush retry, and enabled-plus-empty API-key generation with persistence/rollback. After INI removal, the missing-DB branch creates its snapshot and returns; every lower LoadConfig path has already loaded the store. Remove only the now-unreachable lower `!_storeLoaded`/else-create/rethrow branches. Retain the field, SaveSnapshotToStore/MarkDirty guards, early first-create error propagation, correction-write dirty retry and generated-key rollback. Loading an unchanged valid DB does not schedule a new save. Unknown/removed scalar keys disappear from the next game-written complete snapshot.

## 3. Shared item factory, explicit screens

`ConfigItemFactory.Create(setting, manager, ...)` builds the existing ToggleConfigItem, IntegerConfigItem or DropdownConfigItem from typed metadata. Getters read `manager.Config`; ordinary setters call the shared typed mutation method. Support only narrow view-local setter and description overrides needed by existing UI behavior.

Both screens use explicit ordered descriptor references. ConfigStage retains System/Drums/Exit, combined resolution, dynamic skin selection/reload, song folders, key mapping, NX import and AutoPlay all/per-lane controls. QuickSettingsPopup retains its Auto Mode presets and current six-setting subset/order. Hidden API/path settings do not gain controls.

Preserve the two existing FFmpeg policies:

- ConfigStage resets an existing non-default Play Speed/Pitch value to default when an unavailable edit is attempted, and appends the existing availability warning to the base description.
- QuickSettingsPopup ignores unavailable Play Speed edits, preserving its current value. It keeps empty item descriptions and does not render a description panel.

The shared factory must not unify these policies. Keep labels, descriptions, formats, category/item order, focus/edit navigation, clipping/scrolling and special-control behavior unchanged. No graphics or FFmpeg dependency enters the persistence layer.

## 4. SQLite-only startup and automation

Remove the INI import branch, obsolete constructor parameter and `AppPaths.GetLegacyConfigFilePath`, including its crash-report prefix registration and related tests. Missing DB creates current defaults and normalized managed paths regardless of a stale INI; the INI is neither read nor deleted. Existing canonical v1 DBs load without migration.

Set `Pooling = false` on both `SqliteConfigStore` connection builders. Keep read-only loading, schema checks and parameterized transactional writes. Link that same store source beside ConfigDbSchema in the recorder; no game/MonoGame project reference. `SourceConfigDatabase.Load` delegates to the shared store's Load while retaining caller path/source validation.

Give the recorder's linked types a distinct namespace. E2E references both assemblies, both grant it internal visibility, and E2E already directly uses SqliteConfigStore; linking an unchanged fully qualified type would cause CS0433 ambiguity. Append `DTXMANIA_RECORDER_CONFIG_STORE` to the recorder project's DefineConstants only. Under that symbol, both ConfigDbSchema.cs and SqliteConfigStore.cs use `DTXMania.VideoRecorder.Config`; otherwise they retain `DTXMania.Game.Lib.Config`. Recorder code/test helpers use the recorder namespace, while game/E2E code keeps the game namespace. Build E2E immediately after linking to verify this boundary. No new project or extern alias is needed.

RecordingSandbox reads the source's logical rows read-only and creates its own app-data config.db. Retain existing owned overrides: generated API credentials/port, API enable, all ten AutoPlay lanes, NoFail, fixed resolution/windowed. Preserve unowned rows and live skin/input/root/modifier settings; do not add a second game-setting registry to the recorder. The game may later drop unknown rows when saving its own snapshot. Never copy a live source DB/WAL/SHM or write source data.

Delete INI serialization and bridge-only escaping/trimming checks; keep real absolute-path requirements and current success/failure ownership semantics. Close handles before game launch. Prove successful sandbox deletion after ordinary disposal without a preceding ClearAllPools call masking a pooling bug.

E2EFixtureBuilder writes canonical rows directly with SqliteConfigStore before launch, including SongRoot.0 and API/display/gameplay values. Manual fixtures omit AutoPlay.N. Remove LegacyConfigPath and migrate every INI reader/editor in support and smoke tests. Delete both ArtifactWriter's bootstrap INI copy and GameplayAutoPlaySmokeTests' per-run INI snapshots; the deterministic fixture code needs no replacement seed artifact. Also delete the profile loop's post-Build config.db deletion: each Build now writes the complete profile snapshot, and deleting it would discard API credentials. Preserve shared songs.db across those profiles.

Because a seeded DB already exists, persistence proof must edit a value away from its seed, exit/flush, assert the actual stored value and verify it after relaunch. In `DrumMapping_ResetViaKeyboard_WipesCustomBindingOnSave`, seed `Key.Z=0` and assert that raw row exists before launch; drive Reset and exit, then read the store directly and assert the row is absent. The existing positive binding test covers capture; this reset test must prove an actual persisted row was removed.

Keep a small permanent `Category=E2E` no-DB startup test with stale INI, using GameProcessDriver without waiting for disabled API health. Let the game create config.db, inspect its completed snapshot read-only, assert defaults/unchanged INI and dispose the process. Never let ConfigManager.LoadConfig create the DB before that assertion. Existing unit first-create/failure tests and seeded bundled-skin coverage remain; no separate manual first-run session is needed.

Update the verified live documentation targets: CLAUDE.md (AGENTS.md is its symlink), MCP/README.md and tools/README.md. Recorder runbooks already use config.db; leave them and the historical HPA-192 benchmark record unchanged. No repository scripts directory or cloud UAT recipe is an edit target; an unidentified external recipe is not a dependency of this PR. Empty the allowedFiles list in DTXPathCompatibilityArchitectureTests when removing the last production DTXPath handling/comments, so reintroduction fails. Preserve legitimate skin/NX INI references. No generated screenshots, databases or other run artifacts belong in git.

## 5. Permanent regression coverage and acceptance

Commit baseline default and representative non-default UI sequences before changing production behavior. Assert exact GetDisplayText() plus Description and item order for ConfigStage categories and QuickSettingsPopup. Expected text must be literal baseline output, not regenerated from the descriptors. Use deterministic skin/root/FFmpeg fixtures and existing headless test seams; preserve separate skin-switcher tests where needed.

Permanent tests iterate `ConfigSettings.All` for defaults and valid non-default codec/SQLite round-trips, and its visible ordinary descriptors for widget construction. A reflection test checks every public read/write scalar property has exactly one matching key/type descriptor or an explicit justified non-persisted exception; also check descriptor/key uniqueness, All registration and that the eight special descriptors are not editable handles. Reflection stays in tests. No disposable “new setting” experiment or shipping dummy setting.

Invalid-input cases apply to codecs that can reject input (bool/int/enum). Strings need their own null/path/API tests, not artificial invalid-string rules. Keep independent expected-value cases for normalization, formatting, events, no-op edits, source preservation and failure handling so tests do not merely repeat the implementation.

The [implementation plan](../superpowers/plans/2026-11-27-hpa-803-implementation-plan.md) defines automated gates and one MCP acceptance scenario on a supported platform, including its persistence restart. Start that scenario from a recorder-created sandbox DB, then cover System, Drums, Quick Settings, edit → save → restart → gameplay/Result and agent-inspected screenshot parity. Capture matching-size/skin/fixture-value baseline views; no mockup is attached. Exact UI-text tests supplement this visual check.

RecorderConfigCompatibilityTests supplies in-process source → sandbox → ConfigManager coverage; PreparedChartRecordingSmokeTests uses an E2E fixture and reaches Performance. Those tests remain, while the single combined MCP scenario proves the actual recorder output launches and plays through Result. Source-byte preservation and cleanup stay in automated recorder/compatibility tests. No second recorder/manual no-DB session, human acceptance gate or second native-platform acceptance is required.

## Risks and guards

| Risk | Guard |
| --- | --- |
| Linked source exposes two accessible store types to E2E | Recorder-only namespace for both shared types; immediate E2E build |
| Generic editing bypasses skin/resolution semantics | Persistence-only descriptors are not assignable to ordinary edit handles |
| A property or descriptor is omitted from persistence | Scalar-property/All coverage, key/type uniqueness and round-trips |
| A shared setting drifts between screens | Shared factory, literal baseline text/order tests, separate FFmpeg tests and MCP screenshots |
| SQLite handles prevent recorder cleanup | Pooling disabled for reads/writes; deletion asserted before safety-net cleanup |
| Seeding creates a false persistence pass or discards API setup | Keep each profile's seeded DB; assert Key.Z exists before reset and is absent afterward; verify changed values across restart |
| Dead-feature deletion affects similarly named live code | Scoped reference audit; retain graphics, key-binding, FFmpeg and NX score contracts |
