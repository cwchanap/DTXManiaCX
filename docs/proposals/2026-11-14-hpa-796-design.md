**Status:** Design-only, revised after GitHub review; **no implementation, builds, or tests** performed in this PR yet.  
**Delivery:** Implement on this **same draft PR branch**, one PR, <=3 engineer days. HPA-795 and HPA-797 are complete; HPA-796 unblocks HPA-799 and HPA-801.

## Goal and current architecture

Simplify the game without altering gameplay, visible UI, stage transitions, crash-report policy, audio or scores:

1. **Diagnostics:** delete low-value legacy writes; route only meaningful, nonduplicate failures through the existing `ILogger` pipeline.
2. **Drawing:** eliminate redundant 1x1 white textures, reuse the existing color-texture cache and extend the existing `ChamferedBox` primitive only where pixel geometry is identical.
3. **Stage data:** use two immutable, typed payloads instead of string-keyed dictionaries; delete the unused song-ID copy.
4. **Guardrails:** one short architecture test prevents all three forms of duplication from returning.

Verified seams:
- `IStageGame.LoggerFactory` supplies loggers; `CrashReportRuntime.CreateLoggerFactory` already registers Console and `CrashLogBufferProvider`. Its default minimum level is Information. Legacy `Debug.WriteLine` is absent from Release, while `LogInformation` and above add new Release output. The crash buffer has **500 records**, and its `CrashLogFieldPolicy` only preserves recognized `CrashLogEvents` events/templates; other messages become sanitized `[UNCLASSIFIED MESSAGE OMITTED]` records that still consume slots.
- `ResourceManager.CreateTextureFromColor(Color.White)` already caches `__Color|...` entries; `LaneBackgroundRenderer` demonstrates holding `ITexture` and calling `RemoveReference()`. Color entries survive skin-cache eviction. `ManagedTexture.RemoveReference` does not dispose the texture, but the resource manager may later collect unused entries; each consumer must reacquire on next activation.
- `Lib/UI/ChamferedBox.cs` already owns borrowed-white-pixel fill/chamfer/border drawing. Current edges differ: `GaugeDisplay` uses 2px thickness, `DefaultGraphicsGenerator` uses configurable thickness, and `NotationStripRenderer.DrawOutline` avoids double-drawn alpha corners.
- `IStageManager.ChangeStage(..., Dictionary<string, object>)`, `IStage.Activate`, `StageManager` and `BaseStage` own the transition contract. The live flow is SongSelection -> SongTransition -> Performance -> Result. `songId` is forwarded but not consumed by Performance; it can be obtained from the selected song if ever needed. The `BaseStage` dictionary accessors have no production callers outside BaseStage itself.
- The canonical tests are in `DTXMania.Test/DTXMania.Test.csproj` (.NET 10). HPA-797's existing E2E test journeys produce bundled CX Neon screenshots; this ticket has no new mockup.

## Decision A — Logging: delete first, preserve intentional Release failures

- Remove noisy trace statements (navigation, drawing, parsing iterations, cache hits, per-frame/per-note diagnostics) rather than converting them to `LogDebug`/`LogTrace`. Those levels are filtered today, so conversion creates work without extra observability. Leave `Debug.Assert` and `Trace.Assert` intact.
- Convert **meaningful failures** to structured `LogWarning`/`LogError(exception, "Template {Field}", value)` only where logging already exists or is inexpensive to supply: stages via `IStageGame.LoggerFactory`, `ResourceManager` via its factory, and `SongManager` at its existing bootstrap/composition seam. Avoid loggers across dozens of leaf panels, renderers and parsers.
- Delete leaf texture/audio/font-load-failure messages **when the same failure is already reported by `ResourceManager.OnResourceLoadFailed`**. Log that event once at Warning with path and exception at the resource owner. For failures not delegated to ResourceManager (e.g. `TabHudDisplay` directly acquiring fonts), keep deliberate Release visibility through its parent stage or one targeted logger; do not silently delete the only signal.
- Preserve intentional Release-visible performance errors (e.g. `PerformanceStage.LogPerformanceError`, `TabHudDisplay` font fallback) by routing them to Error through the existing logger/Console provider, with exceptions where available.
- Keep `Console.Error` bootstrap/last-resort reporting in `Program.cs`, `CrashReportRuntime` and equivalent pre-logger paths. It is not ordinary `Console.WriteLine` debug chatter.
- **Do not modify** `CrashLogBufferProvider`, the `CrashLogFieldPolicy` allowlist/privacy rules, factory minimum level, or `CrashLogEvents` registrations. Do not claim a new unclassified warning's text will appear in crash reports. Avoid new Information-level messages; ensure any remaining Warning/Error is rare and useful. Avoid duplicating one exception at resource and caller levels.

## Decision B — White pixel and exact drawing geometry

- Acquire the white pixel from `IResourceManager.CreateTextureFromColor(Color.White)` once per active owner; store its `ITexture`, draw using `.Texture` in current `SpriteBatch`, and release with **`RemoveReference()` only**. Do not call `Dispose()` on cached resources. Existing manager cache and disposal semantics stay unchanged; no second cache/service.
- Extend existing `Lib/UI/ChamferedBox.cs`: expose its current `Fill` helper and add `Border(..., int thickness = 1, float depth = 0f)` with **overlapping-corner geometry** for ordinary rectangular borders. When chamfer is zero, `ChamferedBox.Draw` may delegate to these; preserve its existing chamfered/diagonal drawing for nonzero chamfer. No new `UiPrimitives.cs`.
- Migrate only callers with **identical** rectangle/border pixel placement, alpha/blend, thickness, depth and draw ordering. Preserve `NotationStripRenderer.DrawOutline`'s **non-overlapping translucent corners** as a specialized local method. Preserve special geometry elsewhere if needed. Keep `UIPanel`'s existing textured border but remove its empty untextured border branch rather than inventing rendering for it.
- Delete per-site white-pixel factory hooks made redundant by the resource manager (`StartupStage`, `TitleStage`, `ResultStage`, `PadRenderer`); adapt tests to mock `IResourceManager` instead of maintaining two seams. Preserve only hooks with an unrelated genuine purpose.
- Handle resource loss and stage reactivation by reacquiring as needed; assert reuse and reference lifetime in tests without creating a GPU in headless tests.

## Decision C — Two typed records, no compatibility layer

- Introduce one abstract `StageTransitionPayload` record and **two** concrete immutable records in `Lib/Stage`:
  - `SongPlayRequest(SongListNode Song, int Difficulty, ParsedChart? Chart = null)`; Song must be non-null. Use for **both** SongSelection -> SongTransition and SongTransition -> Performance; the second hop sends `request with { Chart = _parsedChart }`. Chart remains optional for the existing parse-on-demand path.
  - `PerformanceResult(PerformanceSummary Summary, SongListNode? Song, int Difficulty)` for Performance -> Result.
- Change `IStageManager`, `StageManager`, `IStage`, `BaseStage` and all producers/consumers/test doubles to accept `StageTransitionPayload?`; preserve the existing no-payload stage transitions and transition timing. Pattern-match expected payload type at each recipient. Preserve ResultStage's no-summary fallback on direct activation.
- Delete `songId` payload fields and the unused mirrored `_songId` fields in SongTransitionStage/PerformanceStage. Do not add compatibility dictionary overloads, generic property bags or serialization.
- Delete `BaseStage.GetSharedData`, `SetSharedData` and `HasSharedData` plus tests for arbitrary Mode/Screen keys. Migrate real transition tests and Game API mock verifications, including `DTXMania.Test/GameApi/GameApiPreparedChartCommandTests.cs`.

## Guard against recurrence

Add one small `[Trait("Category", "Architecture")]` test file, using the source-tree scan pattern from `DTXPathCompatibilityArchitectureTests`, with three focused facts:

1. No `Debug.WriteLine`, `Console.WriteLine` or diagnostic `Trace.Write*` calls in `DTXMania.Game/**/*.cs` (legitimate `Console.Error` bootstrap paths and `Debug.Assert`/`Trace.Assert` are not banned).
2. No new `Texture2D(..., 1, 1)` allocations outside `Lib/Resources/ResourceManager.cs` (its cache/fallback creation is intentional).
3. No `Dictionary<string, object>` as a stage hand-off contract in `IStageManager.cs`, `StageManager.cs` or `BaseStage.cs`.

Keep the checks source-focused and robust to whitespace/comments; do not add analyzers or a new custom build step. Run in the normal unit suite on Windows and macOS.

## Risks and acceptance

**Risk order:** (1) increasing Release console/crash-buffer volume or losing the only deliberate failure diagnostic; (2) changing border geometry, translucent corner blending or layer depth; (3) losing prepared chart/selection/result data; (4) incorrectly disposing a shared cached pixel. Do not change renderer draw order or crash-log allowlisting just to satisfy the cleanup.

Acceptance criteria (automated and agent-verifiable; no human approval gate):

- **Windows:** Windows project builds; canonical unit suite and existing E2E journeys pass, preserving selected song/difficulty, parsed-chart reuse, both Lanes and Tab gameplay and result persistence.
- **macOS:** Mac/DesktopGL project builds; same canonical unit suite passes, and graphical stage smoke checks run when a macOS runner is available; unrun checks are reported as unverified, not passed.
- **Visual:** Capture **before and after** bundled CX Neon screenshots using existing HPA-797 stage tours (Title, Config, DrumConfig, SongSelect, Lanes, Tab, Result). Use a one-off Pillow pixel diff to inspect **stable UI regions** for 1px geometry/alpha/layer regressions; account for animated/dynamic text/timing. Explain each changed stable region, verify readability/clipping, and attach evidence to this PR. No new mockup exists.
- **Logging:** Chatter is removed, intentional Release-visible errors still appear through Console-backed `ILogger`, classified crash events remain intact, and unclassified message volume does not displace meaningful crash context. No new `CrashLogEvents`.
- **Architecture/lifetime:** One cached white-pixel source, correctly borrowed/released, no string-keyed stage payloads or unused song-ID mirrors; three new architecture facts pass. Scores, judgement and audio timing are unchanged.
- Android/Linux acceptance is **CI-only** if relevant.

## Non-goals

No new logging infrastructure or crash classification events, no new drawing library/file, new GPU cache, UI redesign, new art/SFX, nullable-codebase migration, input refactor, SongManager architecture split, stage async helper, or backward-compatibility shims for obsolete CX dictionary transitions.
