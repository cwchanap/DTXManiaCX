# HPA-796 — Consolidate diagnostics, UI primitives and stage hand-offs (design)

**Linear:** https://linear.app/cwchanap/issue/HPA-796/cleanup-log-through-ilogger-share-drawing-primitives-type-the-stage  
**Baseline:** DTXManiaCX main at 1c2ac979e7263e8c4eb52ebc7b1f5a35e4795a3a (2026-11-14).  
**Status:** Planning only; this draft PR contains documentation, not the implementation.  
**Delivery:** One implementation PR on **this branch**, target ~2–3 engineer days, hard budget 3 days. HPA-795 and HPA-797 are complete. HPA-796 unblocks HPA-799 and HPA-801.

## Goal

Remove three sources of maintenance friction without changing player-visible behavior:

1. Route meaningful diagnostics through Microsoft.Extensions.Logging.ILogger, which the existing crash-report buffer already consumes.
2. Reuse one resource-manager-cached white texture and a small set of drawing helpers rather than duplicating GPU allocations and rectangle/border code.
3. Replace string-keyed dictionaries at stage transitions with a few typed, immutable payload records.

**Non-goals:** New logging framework/provider, new renderer/scene graph, broad dependency injection redesign, UI redesign, new art or SFX, HPA-799 background-task changes, HPA-801 library split, stage lifecycle redesign, changes to scoring/timing, and compatibility adapters for obsolete CX transition dictionaries.

## Verified codebase seams

- BaseGame exposes an ILoggerFactory on IStageGame. StageManager already uses ILogger, and CrashLogBufferProvider is an ILoggerProvider; legacy Debug.WriteLine remains across stages, resource management, song services and renderers. Console.WriteLine/Trace diagnostics must be inventoried too. Keep Debug.Assert/Trace.Assert assertions as assertions.
- ResourceManager.CreateTextureFromColor(Color.White) already caches color textures under a stable __Color key and preserves them on skin changes. LaneBackgroundRenderer is the working example: hold ITexture, draw via ITexture.Texture and call RemoveReference() on teardown. Other stages/renderers create and dispose independent 1x1 Texture2D instances.
- IStageManager.ChangeStage(..., Dictionary<string, object>), StageManager._pendingSharedData, IStage.Activate(Dictionary<...>) and BaseStage._sharedData form the hand-off contract. Live flows use keys selectedSong, selectedDifficulty, songId, parsedChart and performanceSummary. Source/receiver pairs are SongSelectionStage -> SongTransitionStage -> PerformanceStage -> ResultStage.
- Current unified unit test project: DTXMania.Test/DTXMania.Test.csproj, targeting .NET 10 and referencing the Mac/DesktopGL game project on both OSes. Desktop projects are DTXMania.Game.Mac.csproj and DTXMania.Game.Windows.csproj. HPA-797 provides the Windows player-stage E2E screenshot tour.
- The ticket has no new UI mockup. Before/after default CX Neon screenshots from the existing E2E journeys are the visual reference; this cleanup must not alter the layout.

## Decision A — Logging: use the existing pipeline

- Replace **game production** calls to Debug.WriteLine, Console.WriteLine and diagnostic Trace.Write/Trace.WriteLine with structured ILogger calls. Scope includes DTXMania.Game and its Lib code, not MCP server projects, test tools or historical docs. Preserve assertions and conditional debug diagnostics that are not logs.
- Use the existing IStageGame.LoggerFactory in stages. Inject ILogger<T> or ILoggerFactory into leaf services/renderers at their current construction points when required. For the singleton SongManager, wire the logger at its existing initialization/composition seam. Do **not** add a static/global logger locator or a new logging service.
- Choose levels by effect: Error for failures that prevent an operation; Warning for recovered failures; Information for rare player/session lifecycle milestones; Debug/Trace for per-item parsing, cache hits and verbose diagnostics. Avoid repeated Information/Warning output in Update/Draw/audio callbacks. Prefer structured fields and LogError/LogWarning(exception, ...) to interpolated exception-message-only strings.
- Avoid double logging when a caller already reports the same exception. Logging must remain safe if graphics/audio initialization fails; existing test-only NullLogger patterns can be retained where constructor injection is impractical.
- CrashLogBufferProvider remains the sole collector of crash-report log messages. No second buffer, routing sink, or Debug listener. Do not change its privacy filtering or severity behavior.

## Decision B — Drawing: reuse cached white, only two tiny helpers

- Standardize on IResourceManager.CreateTextureFromColor(Color.White). Acquire a managed reference once per consuming component/stage, use its Texture property in SpriteBatch.Draw and release via **RemoveReference**, not Texture2D.Dispose or ITexture.Dispose. ResourceManager owns the actual cached GPU texture and its lifetime. Color textures already survive skin switches.
- Reuse existing resource-manager dependencies where available; pass IResourceManager from the parent only where necessary. Do not add a new independent pixel cache, static GraphicsDevice, Content asset, or GPU resource service.
- Introduce a small UI primitive utility (e.g., Lib/UI/UiPrimitives.cs) with **filled rectangle** and **1px border** methods. Accept SpriteBatch, white Texture2D, destination rectangle, tint and optional depth; respect existing SpriteBatch.Begin/End and blend modes. Keep any nontrivial specialized drawing near its renderer.
- Remove duplicate white-pixel allocations and redundant rectangle/border helpers in active game UI/renderers. Preserve all geometry, alpha, layering, pixel positions and existing fallback behavior; do not re-style the skin. Update GPU-dependent test doubles and disposal assertions to the borrowed/released managed-texture contract. Headless tests must not silently allocate a real GraphicsDevice.

## Decision C — Typed stage payloads, no string-key compatibility

- Add a minimal abstract StageTransitionPayload record (or marker interface) and **three** concrete immutable records near Lib/Stage:
  - SongSelectionPayload: SongListNode song, difficulty index, database song ID (SongSelection -> SongTransition).
  - PreparedSongPayload: the same selection fields plus optional ParsedChart (SongTransition -> Performance).
  - PerformanceResultPayload: PerformanceSummary, optional selected song, difficulty index (Performance -> Result).
- Replace the dictionary overload throughout IStageManager, StageManager, IStage, BaseStage and the three sending/four receiving stages with StageTransitionPayload? as the optional payload. Existing no-data stage transitions continue passing null. Preserve transition timing/debounce, stage caching and activation/deactivation order.
- Each receiving stage pattern-matches its expected payload; preserve existing missing-data behavior where relevant (e.g., ResultStage's default result summary), but do not build a generic bag or support the old string keys. Remove BaseStage.GetSharedData/SetSharedData/HasSharedData and dictionary-specific state after migrating tests.
- Tests that currently pass arbitrary dictionary keys should exercise the **real typed flow** instead; update mocks and stage helpers, not add deprecated overloads. No serialization or persistence for these in-memory payloads.

## Risk boundaries

- GPU resource lifetime is the highest risk: a stage disposing a shared white pixel can break every later draw. A stage that acquires a color texture must only release its reference.
- Logging of frequent render/input/parsing events can flood crash reports; verify severity and frequency, not just grep absence.
- Typed hand-offs can accidentally drop selected difficulty, song ID, parsed chart reuse or PerformanceSummary. Exercise the full SongSelect -> Transition -> Performance -> Result journey, including cancellation/back to SongSelect and failure results.
- A graphics-only unit test is not screenshot evidence; rely on the existing bundled-skin E2E screenshots.

## Acceptance (end to end, automated/agent-verifiable)

1. **Windows:** Windows game builds and the canonical unit suite runs; Windows graphical gameplay E2E traverses the normal player flow, preserves selection/difficulty/chart/results and produces the existing stage screenshot tour.
2. **macOS:** Mac/DesktopGL game builds and the same canonical unit suite runs; launch/smoke the normal stage loop and confirm no missing UI textures or transition regressions where a graphical runner is available.
3. **Visual:** Compare before/after **CX Neon** screenshots of Title, Config/DrumConfig, SongSelect, Lanes, Tab and Result from existing gameplay tours. Confirm unchanged panel geometry, text, borders, opacity, layer order, clipping and layout (no new mockup exists for HPA-796). Attach evidence to this PR; do not request human acceptance.
4. **Lifecycle:** All stages and renderers share ResourceManager's white pixel, release references safely, and retain valid draws after re-entry/skin changes. Unit assertions cover reference lifetime and border/rectangle geometry.
5. **Diagnostics:** No remaining production Debug.WriteLine/Console.WriteLine/diagnostic Trace.Write calls; representative failures and stage events reach ILogger and the existing crash buffer without per-frame spam.
6. **Contracts:** No string-keyed stage hand-offs remain; unit tests cover all three payload flows and empty-payload stage transitions. Scoring, gameplay timing, audio and the existing appearance are unchanged.
7. Linux/Android are **CI-only** if relevant; do not add manual or device acceptance there.
