# HPA-795 — Delete dead code and migration-era infrastructure (design)

**Linear:** https://linear.app/cwchanap/issue/HPA-795/cleanup-delete-dead-code-legacy-shims-the-startup-tracer-and-db  
**Status:** Design-only; revise within this draft PR before implementation.  
**Delivery:** One PR, <=3 engineer days; unblocks HPA-796 and HPA-797.  
**Reviewed against:** DTXManiaCX main and [PR #229 design feedback](https://github.com/cwchanap/DTXManiaCX/pull/229#issuecomment-6717620479).

## Goal and boundaries

Delete obsolete app-version compatibility and HPA-192 profiling without changing gameplay, song-library behavior, DTX/NX chart compatibility or crash reporting. Replace additive **song** database migrations with a **single SQLite `PRAGMA user_version` marker** and deliberately reset `songs.db` when that version changes. No real users require an app-version migration.

This is a deletion/consolidation task, not an input, logging or database architecture rewrite.

## Verified current code

- Startup timing spans run from `Program.cs`/`Game1.cs` into stages, `SongManager`, `SongDatabaseService` and `StartupSongLoadTimingObserver`. `StartupSongLoadSummary.cs` separately emits `HPA192_STARTUP` with four duration fields carried by `SongImportModels.cs`. The `tools/hpa192` scripts and tracer-only tests are still present.
- **Crash reporting has a real type dependency on the tracer:** `CrashContextPublisher.PublishStartupMilestone`, `CrashLogFieldPolicy` and `CrashReportStore.GetStageOrMilestone` use `StartupCriticalPathMilestone`, currently declared inside the tracer file. Three values are published by `Game1`: `StartupActivation`, `StartupFirstDrawEnd`, `SummaryRequest`.
- Song DB initialization currently has multiple invalid-DB checks: `SongManager.IsDatabaseCorruptedAsync`, `SongDatabaseService.IsValidSqliteDatabaseAsync`, `HasProperUnicodeConfigurationAsync` (really a `__DatabaseVersion` probe), a swallowing `HandleInvalidDatabaseFileAsync`, and exception-message recovery branches. `SongDatabaseService.PurgeDatabaseAsync` already closes/clears connection pools, deletes the song DB and **rethrows** failures.
- `SongDbContext` owns the current EF model. `__EnumerationMetadata` is a separately created runtime cache-freshness table, **not** an EF entity table. `EnsureEnumerationMetadataTableAsync` currently swallows creation errors, which conflicts with stamp-after-success.
- `SongScore.NormalizeStoredBestRank` converts legacy **persisted DB** ordinals; it is called from five external production files **and internally by SongScore.RankName and SongScore.UpdatePerformance**. `NxScoreImporter.MapNxRankToBucket` separately converts rank ordinals from actual NX `.score.ini` input and **must stay**.
- `ConfigManager` already imports `DTXPath` from DTXMania/NX `Config.ini` into the song-root finalization policy. The redundant `ConfigData.DTXPath` **in-memory mirror** can go; the import key cannot.
- `CLAUDE.md` and `AGENTS.md` still list `UIButton`, `UIImage`, `UIList`; both are active agent entry-point documents.

## Decisions

### 1. Remove HPA-192 profiler, preserve crash startup milestones

- Delete `StartupCriticalPathTrace.cs`, `StartupCriticalPathHost.cs`, `StartupTimingTrace.cs`, `StartupSongLoadTimingObserver.cs`, the diagnostic environment variables/early exit, `tools/hpa192/`, and profiler-only tests.
- **Before** deleting the tracer file, define `StartupMilestone` in namespace `DTXMania.Game.Lib.Diagnostics.CrashReporting` (e.g. `StartupMilestone.cs`), with only `StartupActivation`, `StartupFirstDrawEnd`, and `SummaryRequest`. Retarget `CrashContextPublisher`, `CrashLogFieldPolicy`, `CrashReportStore`, `Game1` and their tests to this enum. Keep the sanitizer's `Enum.IsDefined` validation and the `Unknown` fallback for older/unrecognized report milestones. Do **not** replace it with a string or keep the tracer's large enum.
- Delete `StartupSongLoadSummary`, its formatting tests, its path/outcome bookkeeping when used solely for logging, and the four timing `TimeSpan` members in `SongImportModels` plus their stopwatches/call sites. Preserve counts and other production data used for song loading, cancellation and status. Search for bare `HPA192` in **active source, tests and tools**; no HPA192 diagnostics should remain.
- **No replacement timing logger.** If `StartupStage.WriteSummaryOnce` is only there for that report, remove its invocation and method. Crash breadcrumbs and startup state publication are a separate **required** feature and remain. Keep the Game API update-thread queue and screenshots.

### 2. Collapse song DB initialization into one probe and reset

- Add `CurrentSongSchemaVersion = 1`, scoped to **songs.db**, using `PRAGMA user_version`. The separate config DB's versioned store stays unchanged. Reuse the existing song DB initialization call site under its semaphore and the existing throwing `PurgeDatabaseAsync`; do **not** add a fourth reset helper or a metadata/version table.
- If file does not exist: create the schema. If it exists: read `user_version` using the scalar-command pattern in `ConfigDbSchema.ReadUserVersion`, but with a **separate song DB connection explicitly configured `Pooling=False`** and disposed *before* a potential purge. An invalid-SQLite `SqliteException` from the probe counts as mismatch; unrelated I/O/access failures should surface rather than triggering destructive recovery. If mismatched, reuse `PurgeDatabaseAsync` (which clears existing pools) to purge **songs.db only** before creating. Test mismatch deletion on Windows to catch file-handle locks. Version `0` (the pre-policy database) intentionally resets scores/history/bookmarks. Do not silently swallow purge failures or mark initialized after a schema error.
- Call `SongDbContext.Database.EnsureCreatedAsync`, ensure `__EnumerationMetadata` exists (its DDL must **throw on failure**, including at bootstrap), then stamp `user_version`. Set `_isInitialized` only after successful initialization. A partial create left without a stamp is reset next start. Reopen a matching-version DB without recreating it.
- Remove the duplicate corruption probes in SongManager/service, `__DatabaseVersion`/Unicode marker, additive column/receipt migrations, swallowing invalid-file handler (and its 100ms delay), and `InitializeDatabaseAsync` message-matching catch/retry and silently successful `table already exists` branch. Retain SongManager's **explicit** purge-on-request operation.
- Delete `ConfigureUtf8EncodingAsync` and its two startup PRAGMAs (`journal_mode = DELETE` and `case_sensitive_like = OFF`): both are defaults in the current setup, and neither establishes Japanese UTF-8 correctness. **Test actual Japanese text round-trips instead.** Keep normal SQLite model, current receipt CRUD, enumeration metadata reads/writes and in-memory test context constructors.
- Add a small test pinning the pair `CurrentSongSchemaVersion` and a SHA-256 of `SongDbContext.Database.GenerateCreateScript()` plus `__EnumerationMetadata` DDL, **normalizing `\r\n` to `\n` before hashing both inputs** (and using fixed UTF-8 bytes) so Windows/macOS produce the same digest. A changed schema without an intentional version/hash update fails CI with a clear “schema changed → bump version and update hash” message. Place the pinned expectation in tests, not a runtime migration registry.

### 3. Delete genuinely obsolete application shims **after** the DB policy

- Delete `UIButton`, `UIList`, `UIImage`, unused `PerformanceUILayout` legacy aliases/asset layouts, SongChart/SongScore legacy entity shims, `PerformanceStage` old-caller parse/init paths and SongManager reflection-only parsing paths **after verifying** live production references. `PerformanceStageDeterministicTests` invokes `InitializeGameplayAsync` by reflection in three tests: adapt those cases to the surviving `InitializeGameplayCoreAsync`/normal activation setup (and explicit run configuration freezing where needed) rather than leaving failing reflection calls. Delete tests whose only purpose is to assert the deleted shim; keep current behavior tests.
- Once new databases cannot contain unversioned stored ranks, replace **every** `NormalizeStoredBestRank` use (five external callers **and SongScore's own methods**) with canonical `NormalizeRankPercentage`, then delete `IsLegacyOrdinal`/`ConvertLegacyOrdinalToBucket`. **Keep** `NxScoreImporter.MapNxRankToBucket`, which is still required for NX score.ini. Preserve actual rank behavior, especially on import.
- Make `ConfigData.SongRoots` the only in-memory source of song roots. Remove its `DTXPath` mirror, writes and mirror-specific tests, **but retain DTXMania/NX `Config.ini` `DTXPath=` import** in `ConfigManager`, with indexed `SongRoot.N` precedence. Update every test and production call site that reads or writes the removed mirror, including `DTXMania.Test/BaseGameTests.cs`, `DTXMania.Test/Stage/ConfigStageNxImportTests.cs` and `DTXMania.E2E/Fixtures/E2EFixtureBuilderTests.cs`; do not remove their `DTXPath=` fixture input. **`SongRoots` is a get-only `List<string>`:** set its contents with `.Clear()` and `.Add(first)` or set the first element; do not assign `SongRoots = [first]`.
- Update the **two component-list lines each** in `CLAUDE.md` and `AGENTS.md` in this PR. HPA-798 owns unrelated document/skin cleanup.

## Non-goals

No general schema migration framework, new telemetry, new startup profiler, full logging conversion, UI rewrite, input stack replacement, test-suite consolidation, historical `docs/superpowers/` purge or compatibility policy for old CX database files. Preserve supported DTX/NX/SET.def, encodings, score.ini, MusicXML/GP imports, gameplay and crash reports.

## Acceptance

- Windows and macOS game/test suites pass; on a draft, trigger the existing `build-and-test.yml` via `workflow_dispatch` using the PR branch after each implementation section rather than waiting for Ready for Review.
- All three published crash startup milestones still validate as a closed enum and appear in crash reports; Game API health/screenshots and normal Title transition still work.
- Fresh songs.db has complete schema, `__EnumerationMetadata` and `user_version=1`; Japanese content round-trips; matching-version restarts preserve ranks, scores, history and bookmarks; invalid or version-0 DB resets, and failed purge/metadata creation does not report success.
- `NormalizeStoredBestRank`, the profiler graph and active `HPA192` markers are gone, but `NxScoreImporter.MapNxRankToBucket` and genuine DTX/NX compatibility remain.
- Indexed song roots and DTXMania/NX `Config.ini` `DTXPath=` inputs still resolve; the config database is never purged.
- No references to removed UI components remain in the active entry-point agent docs.
