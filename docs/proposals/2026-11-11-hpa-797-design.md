# HPA-797 — Lean tests and player-visible screenshot evidence (revised design)

**Linear:** https://linear.app/cwchanap/issue/HPA-797/tests-slim-the-unit-tests-merge-the-mac-test-project-add-an-e2e  
**Review:** [PR #236, review of 2026-11-12](https://github.com/cwchanap/DTXManiaCX/pull/236#pullrequestreview-5870335264)  
**Status:** Design and plan only; no implementation or CI runs performed in this PR.  
**Delivery:** One implementation PR on **this same branch**, target ~2 engineer days, hard budget <=3 days.  
**Prerequisite:** HPA-795 done; this work unblocks follow-up architecture tickets.

## Goal and honest scope

The suite contains duplicated coverage-driven test files, a divergent macOS unit-test project and headless graphics tests that can report `Passed` without rendering. Existing gameplay E2E tests produce screenshots, but several player-facing stages are missing from the uploaded artifacts. Keep useful behavior checks; make the suite cheaper to maintain and the visual evidence complete.

**Do not promise to make test code smaller than game code in this ticket.** The reviewer measured ~45 bucket-named files / 18,092 lines on main (5db4218), about 12% of ~156k test lines; consolidating them alone cannot close the whole ~156k-vs-85k size gap. This ticket removes duplication, establishes better policy and evidence; it is not a wholesale test rewrite.

**Boundaries:** Test source, unit/E2E projects, CI, Codecov, justfile and active contributor docs only. No production/gameplay change, new runner, image diff, graphics framework rewrite, new art, new dependencies or parallel PRs.

## Source findings

- `DTXMania.Test/DTXMania.Test.csproj` already targets .NET 10, references the DesktopGL Mac game project on **both platforms**, and builds on macOS per the reviewer's run. The separate `DTXMania.Test.Mac.csproj` changes package versions, source includes and `MAC_BUILD`. Its exclusion list contains stale entries; it is not needed to make current tests compile.
- Reviewer baseline on macOS: unified project 9,401 / 9,402 tests passed in ~29 s, with one checkout-specific `CxNeonPackTests` failure involving untracked sound assets. Previously excluded classes + `SongSelectionStageTests` passed 207/207. **These are reviewer observations, not reproduced by this planning change**; implementation must recheck on a clean checkout.
- `TestGraphicsDeviceService` opts into real GPU creation only with `DTXMANIACX_ENABLE_GRAPHICS_TESTS=1`. Current device-dependent tests often early-return, so default CI can count nonexecuted graphics assertions as Passed. The Mac filter proposed in the original design would not repair this.
- `codecov.yml` currently enforces project and patch 85%, ignoring `NotationStripRenderer.cs` only because its headless draw path could not satisfy the patch threshold. Windows uploads Codecov coverage but **warns and skips** if the report is absent; its Codecov action uses `fail_ci_if_error: false`. macOS requires a coverage file but does not upload one to Codecov.
- `gameplay-e2e-windows` already runs `Category=E2E` and uploads `TestResults/e2e`. Existing captures: Title, Config and Lanes in `DefaultSkinFirstRunSmokeTests`, SongSelect and Tab in gameplay autoplay tests; Result is game-written to the temp appdata Screenshots directory and not uploaded, DrumConfig only captures failure evidence.
- `E2EFixtureBuilder.Build` defaults to a minimal sandbox skin; only `useBundledDefaultSkin: true` proves the real shipping `System`/CX Neon skin. The screenshot evidence must use the **bundled default skin**, not mixed sandbox art and fallback.
- `DTXMania.E2E/AssemblyInfo.cs` already declares `[assembly: CollectionBehavior(DisableTestParallelization = true)]`: xUnit E2E tests are **serialized**, so the reviewer's concurrent-test race premise does not apply to this assembly. However, sharing a fixture artifact root would still overwrite common files such as `game-stdout.log` and `bootstrap-Config.ini` across sequential tests. Preserve test-specific diagnostic roots and publish only unique tour PNGs to one common folder.

## Decisions

### 1. One canonical unit test project and truthful GPU skips

- Keep `DTXMania.Test.csproj`; delete `DTXMania.Test.Mac.csproj`, redundant `MAC_BUILD` branches and active references in workflow/justfile/CLAUDE.md. Run the same normal `dotnet test DTXMania.Test/DTXMania.Test.csproj` command on macOS and Windows, **no platform-specific traits or test filter**. Keep separate Automation, VideoRecorder and E2E projects.
- Introduce two tiny test-only xUnit attributes, `GraphicsFactAttribute : FactAttribute` and `GraphicsTheoryAttribute : TheoryAttribute`, sharing the `DTXMANIACX_ENABLE_GRAPHICS_TESTS == 1` opt-in check. When graphics is disabled, both assign an explicit `Skip` reason. Use on methods whose assertions require a real GraphicsDevice, not on entire mixed classes; keep headless logic tests as normal Facts/Theories. **Device-gated theories already exist** in `GPURenderingSnapshotTests` (sprite scaling), `ResourceManagerTests` (box.def skin path), and `SongBarRendererTests` (lamp/title textures). Do not add a test-category taxonomy.
- Remove redundant test-local env checks where the attribute replaces them. `TestGraphicsDeviceService` may retain the opt-in guard for callers, but an explicitly enabled graphics test **must fail**, not silently pass, when device creation fails. Do not count a skipped device test as visual evidence.
- macOS builds the same sources and retains FFmpeg runtime checks. Existing compiler/platform problems, if discovered in a clean checkout, are fixed minimally rather than introducing another project or broad exclusions.

### 2. Coverage: project gate only, with real upload failure behavior

- `codecov.yml`: enforce project **80%**, zero threshold and missing-report failure; patch percentage `informational: true`. Delete the obsolete `NotationStripRenderer.cs` ignore **unconditionally**; if whole-project coverage drops below 80%, address actual behavior tests, not exclusions.
- Windows coverage is authoritative for Codecov: fail the step if the expected Cobertura file is missing; set `fail_ci_if_error: true` on the upload so transport/config failures fail CI. Verify the Codecov project status is enforced by branch policy (or explicitly report that it isn't); action success alone does not make an external coverage check required for merging.
- macOS runs unit tests without unused XPlat coverage collection or the orphaned macOS coverage-file existence check. Keep its test exit code, separate audio/recorder tests and FFmpeg validation; do not promise a second Codecov report.
- Capture **per-game-file line and branch coverage** from Cobertura before and after bucket consolidation. Document a small one-off Python or PowerShell XML-to-CSV command in the PR notes (no permanent helper), keyed by Cobertura `class@filename` and aggregated per production file. Extract covered/total source lines from `<line hits>` and branch counts from available `<condition coverage>`/branch metadata; don't use only a project-wide percentage. Diff the sorted before/after CSVs and explain every file with fewer covered lines/branches. This is a regression signal, **not proof that all behavioral assertions survived**; inspect the large bucket classes for unique cases.

### 3. Reuse existing E2E journeys for seven screenshots

**No new E2E tour test file, no new launcher and no extra game launch.** Collect a cohesive seven-screen tour through **existing** E2E tests, all configured with `useBundledDefaultSkin: true`. The required artifacts (distinct filenames under `TestResults/e2e/hpa-797-tour/`) are:

| Stage | Existing owner and minimal modification |
| --- | --- |
| Title | `DefaultSkinFirstRunSmokeTests`, already captures |
| Config | `DefaultSkinFirstRunSmokeTests`, already captures |
| DrumConfig | In the same first-run journey, jump from Config via existing `ChangeStageAsync("DrumConfig")`, wait for fade, capture, then return |
| SongSelect | Capture in first-run journey before opening the song status panel |
| Lanes Performance | Existing first-run capture, but wait for *mid-song with visible notes*, Lanes telemetry and no transition (readiness alone can capture a blank READY state) |
| Result | Continue the first-run autoplay to complete Result/reveal; copy the existing game-written valid `result-*.png` from temp AppData Screenshots into the uploaded tour folder |
| Tab Performance | Reuse `GameplayTabAutoPlay_ShouldJudgeEveryNoteInEffectiveTabModeAndComplete`, switch its fixture to bundled default skin and put its already required mid-song capture in the tour folder |

- Prefer the existing `E2EStageHelpers`, `DefaultSkinFirstRunSmokeTests` PNG integrity guard and `GameplayAutoPlaySmokeTests` completion polling; move small helpers to `E2EStageHelpers` only when genuinely reused. Never duplicate the process driver or large fixtures.
- Screenshot captures must be required assertions (nonempty, complete 1280x720 PNG; Game API stage/style checks where applicable). The first-run fixture uses `extraChartBars: 8` (roughly 24 seconds): after the Lanes mid-song capture, explicitly wait for the **Result stage with `StageCompleted`** using the existing completion helper, then independently poll the game-written `result-*.png` until its PNG signature and trailing IEND are present before copying. `StageCompleted` alone is not screenshot readiness. Wait for DrumConfig fade to settle; use bounded waits.
- Keep each existing E2E test's `fixture.ArtifactRoot` in its **own named subfolder** (`default-skin/` and `tab-autoplay/`). Copy/route **only the seven required PNGs** to a sibling `hpa-797-tour/` folder under the CI artifact root; use an explicit destination or a small copy after validating a local screenshot. Never point two fixture roots directly at the common tour folder, even though the E2E suite is currently serialized.
- Reuse existing Windows E2E CI job and its artifact upload. This is a seven-stage **artifact tour** across existing tests, not a demand that one xUnit Fact separately visits Tab and Lanes. Existing E2E already exercises both modes.
- No pixel baselines, image classifiers or macOS graphical E2E in this task. Inspect actual seven screenshots manually as part of Windows acceptance, comparing with the existing skin/UI mockups in the Linear ticket if provided (HPA-797 has none).

### 4. Small-file consolidation; inspect the large buckets

- Inventory `*Coverage*.cs`, `*Additional*.cs`, `*Patch*.cs` on the implementation base. Reviewer's main snapshot: **45 files, 18,092 lines**, top five totaling 8,196 lines; remeasure after HPA-795.
- Move small, straightforward bucket suites into the component's normal `*Tests` file largely unchanged; remove only obvious duplicate assertions/setup. Reserve careful behavioral triage for the ~8 largest files, where most cases and potential uniqueness live.
- Keep distinctive tests for parsing/timing, persistent scores, input, judgement and lifecycle. Do not rewrite reflection-constructed stage suites; their architecture tickets own that work. Do not remove tests merely to green a build.
- **Evidence:** preserve before/after test counts, per-file Cobertura line/branch coverage, meaningful assertions from the large buckets and a short reason for each material coverage decrease. Coverage sameness alone does not certify semantic equivalence. Avoid claims of exhaustive proof.

## Risks and mitigations

1. **Lost behavior despite green tests or similar coverage:** mechanically preserve smaller suites; inspect largest suites; compare per-file line/branch coverage and record unexplained regressions. Fix or explain losses, not hide them.
2. **Flaky rendered screenshots:** stage readiness, effective mode, mid-song notes, Result reveal/PNG completion and DrumConfig fade require bounded polling. Never accept missing captures as best-effort.
3. **Coverage upload silently absent:** Windows fails closed on missing report and Codecov upload error; verify the external project status is actually required for merge.
4. **Opt-in graphics tests still fake-pass if a device fails:** both GraphicsFact and GraphicsTheory must fail visibly on opted-in device initialization failure; default headless CI reports Skipped.

## End-to-end acceptance

- Windows and macOS both build/run the one unit test csproj with **the same selection** (headless GPU assertions skipped, not passed); macOS FFmpeg/audio tests remain valid.
- No active references to `DTXMania.Test.Mac.csproj` or `MAC_BUILD`; no bucket-named suite remains and large-suite unique behavior is accounted for.
- Project Codecov coverage >=80% with enforced status and upload; patch informational; no renderer ignore; per-file before/after comparison included.
- The uploaded Windows E2E artifact contains seven valid, visually checked PNGs of bundled CX Neon: Title, Config, DrumConfig, SongSelect, Lanes, Result and Tab. Lanes and Tab each show real mid-song notes, Result is completed/revealed, and diagnostic artifacts remain isolated per test.
- No game behavior, audio semantics, chart parsing or release packaging changes.
