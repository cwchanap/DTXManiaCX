# HPA-797 — Lean test suite and visual E2E tour (design)

**Linear:** https://linear.app/cwchanap/issue/HPA-797/tests-slim-the-unit-tests-merge-the-mac-test-project-add-an-e2e  
**Status:** Design-only, awaiting review. No application or CI changes in this draft.  
**Delivery:** One implementation PR on this branch, targeted at <=3 engineer days.  
**Prerequisite:** HPA-795 is Done (PR #229). This unblocks HPA-796/HPA-799 and subsequent architecture work.

## Problem and goal

The unit suite is larger than the game and contains overlapping test buckets added to satisfy a mandatory 85% patch-coverage threshold. Meanwhile macOS compiles a second, divergent test project with an exclusion list. The 2026-11-07 UI playtest still found visual defects despite high coverage.

Simplify the existing test setup, retain meaningful behavioral assertions, and make real-render screenshots of all important player-facing stages available from CI. This is **test/CI/docs-only**; no production architecture, gameplay changes or pixel-perfect screenshot baselines.

## Verified repository seams (main, 2026-11-11)

- `codecov.yml`: mandatory project and patch thresholds at 85%, plus a renderer-only coverage exclusion.
- `DTXMania.Test/DTXMania.Test.csproj`: primary .NET 10/xUnit test project; already references `DTXMania.Game.Mac.csproj` and uses recent test SDK / coverlet packages.
- `DTXMania.Test/DTXMania.Test.Mac.csproj`: duplicate build graph with older test SDK/runner, explicit `Compile` exclusions and `MAC_BUILD`. `SongSelectionStageTests.cs` has conditional `#if !MAC_BUILD` blocks that need consideration when the flag disappears. Some excluded files are headless-safe; do not permanently lose them by default.
- `DTXMania.Test/Helpers/TestGraphicsDeviceService.cs`: real-device setup is opt-in via `DTXMANIACX_ENABLE_GRAPHICS_TESTS=1`. Existing GPU/draw tests may silently return without a device; classification is not the same as successful visual verification.
- Existing overlapping buckets include `PerformanceStageCoverageTests`, `PerformanceStageAdditionalCoverageTests`, `SongSelectionStageCoverageTests` and `PreparedGameplayAudioSetCoverageTests`. Linear's prior audit counted roughly 46 bucket-named files / 18.5k lines. Re-inventory on the implementation branch because HPA-795 has landed.
- `.github/workflows/build-and-test.yml`: Windows currently runs the primary test project; macOS builds/runs Test.Mac. The separate `gameplay-e2e-windows` job already runs `Category=E2E` and uploads the entire `TestResults/e2e` tree.
- `DTXMania.E2E/Support/E2EStageHelpers.cs` already has stage polling, song startup and Game API screenshot capture. `DefaultSkinFirstRunSmokeTests` captures Title/Config/Performance; `DrumMappingStageSmokeTests` navigates DrumConfig; `TabImportSmokeTests` runs Tab to Result; `GameplayAutoPlaySmokeTests` runs Lanes and verifies Result. `E2EFixtureBuilder` supports deterministic charts and `DrumsNoteDisplayStyle.Tab`. These are precedents, not a reason to make more harness abstractions.

## Decisions

### 1. Coverage should describe the whole project, not coerce every patch

- Make the Codecov **project** target 80% with `informational: false` and its existing zero threshold / missing-report failure. Keep it as an actual gate.
- Make **patch** coverage informational only (retain the displayed percentage as guidance, but never require tests written solely for patch percentage). Remove the former renderer-only ignore if the measured project coverage still passes without it; prefer honest whole-project coverage.
- Preserve the existing coverage generation and artifact upload in both CI jobs. Confirm the coverage report is present; passing because it was not uploaded is not acceptable.

### 2. One canonical test project across Windows and macOS

- Keep `DTXMania.Test.csproj` as the only unit project and delete `DTXMania.Test.Mac.csproj`. Do not create a third project or duplicate test sources.
- Explicitly tag tests which **require** a real GraphicsDevice (proposed `[Trait("Category", "GraphicsDevice")]`), at class level only when the entire class requires it. macOS CI excludes that trait with `--filter "Category!=GraphicsDevice"`; leave all other tests available to macOS. Preserve xUnit's other categories.
- **Execution filtering does not fix compilation.** Audit the previous Mac exclusion list, plus `MAC_BUILD` code guards. Repair portable compilation or narrow platform-specific test dependencies where needed rather than reintroducing whole-file `Compile Remove` lists. Remove obsolete `MAC_BUILD` branches/flags. Treat a previously excluded headless logic test as a real test to run, not a GPU test to hide.
- Windows keeps its current applicable tests. GPU opt-in remains optional for a local graphical run; do not mistake a silently skipped graphics test for passing screenshot verification.
- Update `justfile`, `CLAUDE.md`, workflow commands and other *active* documentation referencing the removed project. Historical evidence can remain unchanged.

### 3. Consolidate test buckets without throwing away behavior

- Inventory `*Coverage*`, `*Additional*`, and `*Patch*` named test files (and matching suites), grouped by real component/behavior.
- For each test, **keep distinct behavioral/edge-case assertions** in the established owning suite; delete exact duplicates, reflection-only shape checks without behavioral value, and setup whose only purpose was to touch lines. Only then delete bucket-named files.
- Keep existing deterministic and integration tests for chart timing/parsing, SQLite, gameplay judgement, resource loading, and stage lifecycles. Do not rewrite all reflection-constructed stage tests here; owner refactor tickets handle that.
- Do not delete tests to silence new failures. Fix tests which became portable under the single project, with no production behavior changes.

### 4. One deterministic seven-screenshot stage tour

Create one `Category=E2E` test (for example `StageScreenshotTourTests`) using the **existing** out-of-process launcher, fixtures, Game API and screenshot helpers. Required named PNGs:

1. Title
2. SongSelect
3. Lanes Performance
4. Tab Performance
5. Result
6. Config
7. DrumConfig (drum key mapping)

Use a real game process and deterministic autoplay/chart fixtures. Wait on stage telemetry and readiness (especially `PerformanceReady` and the display style) before capture; validate nonempty, complete PNG bytes and fail if any capture is missing. Scope artifacts to a unique tour folder to avoid overwrites. Keep a bounded transition/render settle for animated stages rather than unbounded sleeps.

Two short launches/configured fixtures **within the same test** are fine if necessary to exercise both Lanes and Tab. The tour is evidence of what was rendered, **not** an image-diff gate or a replacement for unit tests. Reuse existing Windows E2E job/artifact upload; do not introduce a new runner, image snapshots, display protocol or dependencies.

## Non-goals

No pixel diffs, GPU infrastructure rewrite, macOS graphical-E2E parity project, new test framework, production refactor, coverage-per-file target, test mocking architecture, new art/audio, or CI acceptance on Android/Linux.

## Risks and mitigations

- **Mac compilation:** trait filtering is runtime-only. Check all formerly excluded sources and `MAC_BUILD` guards, including device-service helpers and platform APIs, before deleting the Mac project.
- **Coverage regression:** some bucket suites may contain unique cases. Compare before/after test inventory and whole-project reports; preserve useful cases and keep the 80% gate mandatory.
- **Flaky screenshots:** render transitions and short charts can race capture. Use existing stage polling, longer deterministic bars and bounded readiness/reveal waits; no arbitrary sleep-only navigation.
- **Time budget:** avoid broad test refactoring. If a truly unique test requires substantial redesign, carry it into the owning suite with minimal changes and report the scope risk rather than hiding it.

## Acceptance

- A single `DTXMania.Test.csproj` builds and runs on Windows and macOS; no stale project references or macOS blanket source exclusions.
- No bucket-named test files remain; uniquely valuable behavioral checks have owners in normal suites.
- Project Codecov gate is 80% and enforced; patch coverage is informational. Coverage artifacts remain valid.
- A Windows CI gameplay E2E run produces seven distinct, valid stage PNGs in the uploaded artifact, including separate Lanes and Tab gameplay captures.
- Existing game behavior, current audio/recorder tests, and both operating systems' build/test paths remain green.
