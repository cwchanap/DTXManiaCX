# HPA-798 — Canonical CX Neon System skin and repository docs (reviewed design)

**Linear:** https://linear.app/cwchanap/issue/HPA-798/repo-make-cx-neon-the-system-skin-and-refresh-claudemd-and-docs  
**GitHub:** https://github.com/cwchanap/DTXManiaCX/pull/235  
**Status:** Design for review; no production implementation or verification yet.  
**Delivery:** One PR (this draft), <=3 engineer days.  
**Review incorporated:** PR #235 design review, 2026-11-10. The project lead confirmed the original CX-Neon-default / NX-removal scope.

## Goal and current evidence

A clean checkout should run and ship the **same CX Neon default skin** without local setup. Preserve custom skins and existing runtime resolution. Remove NX/GITADORA-derived graphics from the **current tracked repository tree**, not Git history. Correct stale agent documentation and delete specified obsolete docs.

- Today, `System/Graphics` and `System/Theme.ini` describe the old NX skin, while the release jobs flatten `System/CXNeon/{Graphics,Sounds,Theme.ini}`. The old art must not ship. Existing local checkouts can also have **ignored** NX-era `System/Sounds` and `System/Script` files.
- `AppPaths.GetBundledSystemSkinRootCandidates` already supports `<exe>/System` and macOS `Contents/Resources/System`. `ConfigManager.ResolveSkinPath` already maps the relocatable `Default` token to the validating bundled root. `PathValidator.IsValidSkinPath` recognizes the shipped CX Neon backgrounds. **Do not change runtime skin loading.**
- The two game `.csproj` files do not copy repository `System` into build/publish output. Their existing OFL license / BundledSongs `None` items provide the exact MSBuild pattern to extend.
- `AGENTS.md` is a Git symlink to `CLAUDE.md` (mode `120000`); it is **not** a second source document. Preserve that symlink.
- `tools/practicegen/practicegen.py` currently reads click sources from `System/CXNeon/Sounds`, alongside skingen, sfxgen and tests that assume the old path.

## Decision 1: One canonical source pack (no generated art work)

After implementation:

```text
System/
  Theme.ini
  Graphics/       # original CX Neon files moved, unchanged
  Sounds/         # original CX Neon OGG files moved, unchanged
  README.md       # short skin provenance and generator reference
```

- Remove the tracked NX `System/Graphics/**` and old `System/Theme.ini`. Move the committed CX Neon `Theme.ini`, `Graphics/**`, `Sounds/**` into root `System`; remove `System/CXNeon`. Source art stays in `tools/skingen/source`, unchanged.
- **Fix `.gitignore` as part of the move.** Drop `System/*` and its narrow allowlist; track `System/**` except non-asset junk (`desktop.ini`, `Thumbs.db`, `*.log`, `.DS_Store`). This only affects Git status; MSBuild globs still see ignored files, so the project files must separately exclude this junk.
- Audit old checkouts **before** changing ignore rules with `git clean -ndX System/` (dry-run only). Afterward inspect `git status --untracked-files=all -- System/` and reconcile leftover NX `Sounds`/`Script` files before build/publish. Do **not** automatically clean or delete unrelated local user data. The submitted asset pack must contain only reviewed CX Neon files.
- Preserve asset bytes and paths relative to the skin root. No asset regeneration, no runtime fallback shims, no Git-history rewrite, no auto-removal of app-data skins.

## Decision 2: Retarget the existing asset pipeline

- `tools/skingen/skingen.py`: default compose/validate pack becomes `System`. Remove `NX_PACK_ROOT` and the bootstrap “fill missing dimensions from NX” branch: after the relocation that branch would incorrectly measure CX Neon against itself. Required unmeasured dimensions remain explicitly authored in the manifest.
- `tools/sfxgen/manifest.json`: output becomes `System/Sounds`. Keep the existing validator; expose an optional `validate --out-dir <dir>` parameter to reuse `validate_pack(manifest, out_dir)` against published assets.
- `tools/practicegen/practicegen.py`: click source becomes `System/Sounds`; run its generator and ensure committed `BundledSongs` output does not change.
- Retarget `tools/skingen/test_skingen.py`, `CxNeonPackTests`, CI workflows and active tool docs. Remove **all** “pack not produced yet; pass/skip” guards in the C# pack tests (including the theme-only reference check) and applicable release steps; a committed default pack must be mandatory.
- Search both literal and composed path references with `git grep -n -i cxneon -- ':!docs'` plus targeted searches for `System` / `Sounds` path construction; legitimate CX Neon product names and test fixture names may remain, but no active path to the obsolete nested pack.

## Decision 3: Build/publish and package the same skin once

- Add three explicit MSBuild `None Include` items in **each** game project, following the existing license/BundledSongs pattern. Use `Link="System\Theme.ini"` for the single theme file. For the external recursive `Graphics` / `Sounds` globs, use **`LinkBase="System\Graphics"`** and **`LinkBase="System\Sounds"`** respectively, so `%(RecursiveDir)%(Filename)%(Extension)` preserves every subdirectory and filename. Set both `CopyToOutputDirectory="PreserveNewest"` and `CopyToPublishDirectory="PreserveNewest"`. Do not use a literal `Link` naming only the destination directory; no shared MSBuild target.
- Add an explicit per-item `Exclude` to both recursive globs for `**\*.log`, `**\.DS_Store`, `**\desktop.ini` and `**\Thumbs.db` under their respective source roots. Gitignore does **not** prevent physical filesystem files from being included by MSBuild. Check the actual build/publish output has no junk metadata or legacy NX files.
- Referencing test projects inherit game content. This means tests that previously saw no bundled skin may now resolve the test output's `System`. **Run the Mac unit suite immediately after MSBuild changes** and adapt tests only using existing `baseDir` overloads/test seams, not by blocking content flow.
- Windows portable output now contains `System`. Inno's recursive `SourceDir` already picks it up: delete the redundant `SystemSkinDir` macro/`[Files]` entry and release staging. Retain `[InstallDelete] {app}\System` for safe upgrades; keep custom app-data skins untouched.
- macOS publish output has `System` next to the executable for direct dev runs. When building `.app`, **move** `Contents/MacOS/System` into `Contents/Resources/System` (existing supported bundled candidate), with no duplicate `MacOS/System`. Update `installer/macos/test-build-dmg.sh` to create its fake skin **inside `$PUBLISH/System`**, invoke the new four-argument builder, and assert `Resources/System` exists while `MacOS/System` does not.
- Remove old CI/release “flatten CX Neon” and “compare published skin with NX source” steps. After source relocation that equality check would compare published content with its own source and prove nothing. Instead run existing `skingen validate --pack <published-System>` plus the small `sfxgen validate --out-dir <published-System/Sounds>` extension; missing required assets fail closed. Avoid a new shell-based “no NX” assertion framework.

## Decision 4: Bounded documentation cleanup

- Edit `CLAUDE.md` alone; **keep `AGENTS.md` as a symlink**. Fix actual stage list (includes DrumConfig), project map (`DTXMania.Automation` and `DTXMania.VideoRecorder`), .NET 10 commands, Mac/Windows test paths, asset layout and generator workflow. Avoid hard-coded component counts.
- Delete `docs/superpowers/` and five verified stale implementation snapshots: `docs/skin-system-implementation.md`, `docs/graphics-management-implementation.md`, `docs/song-data-management-system.md`, `docs/song-selection-system-implementation.md`, `docs/stage-transition-system-implementation.md`. These describe obsolete NX/default layouts, old `DTXMania.Shared.Game` paths or JSON-based song storage.
- Repair the **five known active references** to `docs/superpowers`: `.coderabbit.yaml`, `DTXMania.Game/Content/Bravura-Notation.spritefont`, `DTXMania.Game/Lib/Song/Components/SongStatusPanel.cs`, `DTXMania.Game/Lib/Song/NxScoreData.cs`, `DTXMania.Test/Stage/Performance/PreparedGameplayAudioSetBenchmark.cs`. Remove obsolete links or point to current source/`System/README.md` where meaningful.
- Retain `docs/proposals` (including this PR), verification evidence, recorder docs, useful reference material and the remaining current documentation. No open-ended documentation audit or fresh docs architecture.

## Verification/risks and acceptance

**Risks identified by review:** (1) ignored, locally leftover NX files could silently be shipped by a glob; require a deliberate working-tree audit and explicit MSBuild junk exclusions. (2) the bundled `System` directory appears in test output and can flip tests that assumed no bundled skin; run tests right after MSBuild copying. (3) wildcard metadata and an obsolete five-argument DMG fixture can break packaging; explicitly set `LinkBase` and update the fixture as part of the builder change.

- Clean checkout, clean app-data (`DTXMANIA_APPDATA_ROOT` temporary directory), Windows E2E and macOS real run all start with CX Neon. Capture macOS screenshots; existing Windows gameplay E2E is the preferred Windows evidence.
- Local developer setups previously activated with `just install-cx-neon true` may still point at a symlink to the deleted folder or retain app-data NX art. **Document a manual developer-only cleanup**: remove stale `<appdata>/System/{CXNeon,Graphics,Sounds,Script}` only after checking local customizations, then reselect `Default`. No automatic migration or deletion of player data.
- Source and published texture/audio validators pass. Practicegen output has no diff. Mac + Windows unit suites, installer compilation, DMG smoke and CI pass; package has exactly one default skin in the correct place.
- `AGENTS.md` remains a symlink and active docs contain no broken links into deleted `docs/superpowers`.
- No gameplay, configuration schema, Git history, SFX/art regeneration, arbitrary runtime refactor or unrelated documentation work.

**One existing PR for all steps.** The design is documentation only until the implementation agent commits actual source changes and test evidence.
