# HPA-802 — Split SongSelectionStage by responsibility

**Linear:** https://linear.app/cwchanap/issue/HPA-802  
**Implementation:** [one-PR plan](../superpowers/plans/2026-11-24-hpa-802-implementation-plan.md)  
**Baseline:** main `ec07f14472fc92217ce560fc7f30c5779074a2c1` (2026-11-24). HPA-799 and HPA-801 are Done and present in main.  
**Status:** planning only; no production edits, builds, gameplay or tests executed.

## Objective

The current `DTXMania.Game/Lib/Stage/SongSelectionStage.cs` is 4,077 lines, mixing preview audio, tab query/persistence state, library publication intake, UI projection, input and transitions. Extract three cohesive concrete owners under `Lib/Stage/SongSelection/`. The stage remains the UI coordinator and owns lifecycle, layout, input, browse navigation, search/filter UI, selection/difficulty, prepared-chart resolution/projection and transitions. No behavior or visual changes.

One PR (this draft), at most three engineer days including test migration and acceptance. No DI container, generic framework, new service interfaces, event bus, compatibility layer, new assets, database/schema changes, query rewrites, audio timing changes, or general Song Select redesign. Do not reopen HPA-799 or HPA-801. Use the current .NET 10 toolchain and unified `DTXMania.Test.csproj`.

## Ownership and dependency direction

| Owner (proposed concrete internal class) | Owns | Collaborators |
| --- | --- | --- |
| `SongSelectionPreviewController` | Preview sound/instance refs, delayed start, BGM reference/instance and fades, prepared-preview lifecycle and elapsed/identity state | Existing resource manager, logger, explicit path and prepared selection supplied by stage |
| `SongSelectionTabs` | Active tab, recent/bookmark caches and error/empty projection state, refresh generation, query requests, bookmark optimistic mutation and ordered persistence/rollback | Game-owned `SongLibrary.Queries`, applied snapshot accessor, logger, activation scope passed explicitly |
| `SongSelectionLibraryIntake` | Publication subscription, initialization readiness, coherent applied snapshot, version marker, active roots, score identity index, flat-list eligibility and library-empty classification | Game-owned `SongLibrary`, existing activation scope, narrow stage reconciliation/readiness callbacks |
| `SongSelectionStage` | UI, input, navigation stack, selected song/difficulty, filter criteria/view, transitions, prepared chart resolution/projecting guard, drawing, lifecycle | Three concrete collaborators and existing game services |

Keep the collaborators stage-instance lifetime (particularly tab writes), with explicit reset/bind/unbind at activation boundaries; do not recreate them per frame or expose their fields for tests. Lazy resource/library resolution where current construction permits uninitialized game stubs: no DB initialization or filesystem work in a constructor. Keep one `SongLibrary` game-owned instance, no new singleton. Use direct concrete constructor parameters and narrowly scoped delegates only for real I/O/test seams. Pass the actual activation scope when scheduling, not a later lookup of `BackgroundWork`. Stage-to-collaborator calls and narrow notifications suffice; no controller-to-controller dependency, circular construction, or passing the entire stage to a helper.

## A. Preview and prepared recording

Current seams: fields 159–162, 201–219; `PrepareVideoChart` / `StartPreparedPreview` / `CancelPreparedChart` / `ActivatePreparedChart` (1341–1496); preview timers/ownership (3118–3379); `SetBackgroundMusic` (3937–3974); telemetry (3980–3996).

- Move the preview and BGM refs, delay/fade timers, sound load/create/stop/release logic, prepared selection record + state + elapsed time into the preview controller. Stage retains ordinary selection policy, resource initialization, path/eligibility validation and browse projection, input/transition logic, and cursor/game-start SFX. Public stage entry points used by GameApi/recorder and BGM handoff remain live delegations/orchestration, not obsolete compatibility methods.
- Stage resolves the exact chart, validates path and file existence **before** disturbing existing preview; suppress intermediate selection events during projection. Only successful load publishes a stopped prepared selection. On projection/load failure resume ordinary primary-chart delayed preview exactly as today. A rejected request must leave existing preparation alone.
- Prepared playback never auto-starts after the ordinary delay, explicitly starts once, loops at existing volume, counts only actual playback time (negative delta clamps), reports failure on unexpected stop without auto-restarting, and keeps identity for telemetry. Preserve current messages and result tuple contract, relative identity rather than absolute path, and speed/difficulty semantics. Stage reads one controller-owned prepared record/state for telemetry and exact node/difficulty eligibility; blocked activation keeps preparation, successful activation clears it then requests SongTransition. Row/difficulty change clears preparation only when current rules require it.
- Preserve existing BGM fade durations/volume bounds, direction changes, managed sound reference ownership, replacement/stop/dispose order, best-effort error handling, and deactivation/repeated cleanup semantics. No second owner of the same sound/instance. Keep navigation SFX stage-owned; do not merge it with preview or change the stage transition handoff. Verify all SetBackgroundMusic callers and recorder RPC callers before moving methods.

## B. Tabs and bookmark writes

Current seams: fields 67–126; active-tab projection/refresh (2183–2254); tab bar and recent label helpers (2838–2882); `SwitchToTab`, loads, bookmark writes (3428–3760). Use existing `SongSelectionTab.Next()`, `BookmarkStateReconciler`, and `SongQueryService.GetRecentlyPlayedNodesAsync(20)`, `GetBookmarkedNodesAsync()`, `SetBookmarkAsync()`.

- Stage still routes Tab/B, pad double hits, overlay suppression, sound feedback, focus reset and visible-list/UI changes. Tabs owns the active tab, switches/reset-to-All on entry, warm-loads Recent and Bookmarks, and exposes projected flat rows plus distinct empty/error states. Stage applies those rows to SongListDisplay and handles All's hierarchical/filtered projection. Pass intake's eligibility filter to the flat-list projection; do not duplicate or destructively trim caches. Preserve recent display labels/order, empty/error text and All/Recent/Bookmarks cycle.
- Use HPA-799 scope `Run`/`RunAsync` for DB query work off update thread; materialize independent result lists before posting. On success/error, update caches/flags only through drain. Keep current Recent completion-order semantics (do not silently change behavior); Bookmarks rejects stale same-activation successes AND failures via its existing load generation, including in-flight loads invalidated by toggle. Scope retirement rejects all old UI work. Keep refresh consumption version/dirty-state protocol so reconciliation cannot swallow an async refresh, and reset stale flags before initial projection.
- Move the **entire** bookmark write path with tab state, not merely query methods. Per-song writes chain after prior writes even if prior failed; last user intent wins. Switching into Bookmarks waits for in-flight writes then posts the load to the captured scope. A committed/in-flight persistence write must survive navigation; only the origin-scope UI rollback drops. Keep the stage-instance pending-write dictionary, per-song toggle generation and revert gate across activation resets. At final stage disposal retain bounded five-second wait/log behavior before the game disposes its library/database.
- Preserve persisted-ID preference, zero-ID selected-node-only flip, immediate cross-representation stars, removal on unbookmark, duplicate SET.def reconciliation, and version-guarded optimistic shared-root update. A current failed write rolls back the applied and latest published root trees plus Recent/Bookmark caches and reloads a wrongly removed bookmark row when appropriate. If origin scope retired, drop UI revert but still perform generation-checked shared-library revert under the same gate as optimistic shared updates. Keep the captured library instance; no callbacks access new activation UI. Do not simplify the concurrency invariants as incidental cleanup.

## C. Library intake

Current seams: fields 129–138; initialization and subscribe/unsubscribe (804–914); initialization result/publication/reconciliation (957–1051); stable chart/root eligibility and empty-state helpers (1607–1843). `SongLibrary.GetLibrarySnapshot()`, `IsInitialized`, `SongLibraryPublished` are the actual HPA-801 API; do not introduce SongManager shims.

- Intake owns the event handler and `BackgroundWork.Latest<long>` reporter bound to the current activation; subscribe/unsubscribe idempotently against the actual library. Producer thread only reports version; on update drain fetch newest coherent snapshot. No worker/UI queue or polling thread. Initialization also uses `Post` to fetch the newest snapshot at drain, not a stale worker-captured tree. Initializer success/failure marks readiness and notifies stage to unblock an open search modal. No scope means no subscription. Retire scope before unsubscribe and UI/audio disposal.
- Keep one authoritative applied snapshot and identity index, not a second copy in stage/tabs. Distinguish no snapshot yet (existing permissive flat-list seam) from an explicitly empty active-root set. Classify no active roots / no supported charts / has songs without changing display copy. Match active-root membership and currently published song/chart identity; exclude dropped/missing chart rows using ExistingCharts, preserve current path normalization. The filter returns projected rows; caches retain hidden rows so re-publication can restore them.
- Stage still owns visible browse state. Use a narrow synchronous reconciliation callback so stage captures previous stable navigation paths and selection identity **before** applying new roots, then intake installs coherent snapshot/index, stage restores navigation and rebuilds filter/flat projection, updates preview roots, restores retained selection or clears removed selection/preview/status, updates breadcrumb/folder hint and completes tab refresh consumption. Only after successful reconciliation advance applied publication marker (including existing max(signal, snapshot.Version) handling). Keep ordering explicit; no partial UI mutation on publisher thread, no early version acknowledgement, and no duplicate stored root list except existing browse projection. Initial entry uses the same path as publication. Existing failure preserves a previously valid snapshot; otherwise clears placeholder and unblocks search.
- Keep stable navigation path and selection restoration in the stage because they are UI/browse concerns; share existing pure path/identity helpers where necessary, without a new generic identity subsystem. Test the intake independently with controlled publication/readiness callbacks and the stage's actual reconciliation separately.
