## Objective

The current `DTXMania.Game/Lib/Stage/SongSelectionStage.cs` is 4,077 lines, mixing preview audio, tab query/persistence state, library publication intake, UI projection, input and transitions. Extract three cohesive concrete owners under `Lib/Stage/SongSelection/`. The stage remains the UI coordinator and owns lifecycle, layout, input, browse navigation, search/filter UI, selection/difficulty, prepared-chart resolution/projection and transitions.

Preserve live behavior and visuals, with **one deliberate narrow behavior fix:** stale Recent load results/errors will no longer overwrite newer requests. Removing verified dead BGM code is not a live behavior change.

One PR (this draft), at most three engineer days including test migration and acceptance. Implement as reviewable commits: dead BGM deletion, preview, intake, tabs. No DI container, generic framework, new service interfaces, event bus, compatibility layer, new assets, database/schema changes, SQL query rewrites, audio timing changes, or general Song Select redesign. Do not reopen HPA-799 or HPA-801. Use the current .NET 10 toolchain and unified `DTXMania.Test.csproj`.

## Ownership and dependency direction

| Owner (concrete internal class) | Owns | Collaborators |
| --- | --- | --- |
| `SongSelectionPreviewController` | Preview sound/instance refs, ordinary delayed start, stopped/explicit prepared playback, playback state and elapsed time | Existing resource manager, logger, explicit audio path |
| `SongSelectionLibraryIntake` | Publication subscription, initialization readiness state, applied snapshot/index, version marker, active roots, flat-list eligibility and library-empty classification | Game-owned SongLibrary, existing activation scope; stage supplies publication signal handler |
| `SongSelectionTabs` | Active tab, recent/bookmark caches and error/empty projection state, refresh generation, unified generation-guarded loads, optimistic bookmark mutation and ordered persistence/rollback | Game-owned SongLibrary.Queries, intake's final snapshot/filter accessors, logger, explicit activation scope |
| `SongSelectionStage` | UI, input, navigation stack, selection/difficulty, filter criteria/view, prepared selection record/projecting guard, reconciliation sequence, drawing, lifecycle, transitions | Three concrete collaborators and existing game services |

Keep the collaborators stage-instance lifetime (particularly tab writes), with explicit reset/bind/unbind at activation boundaries; do not recreate them per frame or expose fields for tests. Resolve resources/library lazily where current construction permits uninitialized game stubs: no DB initialization or filesystem work in a constructor. Keep one game-owned SongLibrary; no new singleton. Use direct concrete constructor parameters and narrowly scoped delegates for actual I/O/test seams. Pass the actual activation scope when scheduling, not a later lookup of BackgroundWork. The stage drives reconciliation in one linear method; no stage passed to helpers, nested orchestration callbacks or cyclic dependencies. Implement intake before tabs so final filter/snapshot accessors exist when tabs is extracted.

## A. Preview and prepared recording

Current seams: fields 159–162, 201–219; PrepareVideoChart / StartPreparedPreview / CancelPreparedChart / ActivatePreparedChart (1341–1496); preview timers/ownership (3118–3379); selection/difficulty handlers (1851, 1957); telemetry (3980–3996).

- Move preview refs, delay timer, sound load/create/stop/release, prepared playback state (None/Prepared/Playing/Failed) and elapsed ms into the preview controller. It accepts audio paths, not SongListNode/SongChart or a browse-selection record. Its small surface is ordinary delayed load, LoadStopped(path), StartPrepared(), Stop()/reset, Update(delta), PreparedState and PlayedMs (names illustrative). The stage retains the PreparedChartSelection(Node, Chart, DifficultyIndex, TelemetryIdentity) record, exact-chart resolution, path/eligibility validation, browse projection and guard, ordinary primary-chart path selection, recorder-facing methods, input/transition policy and navigation SFX. Do not duplicate playback facts in stage or selection facts in controller.
- Stage validates the requested exact chart, preview declaration and file existence **before** disturbing an existing preview/preparation; suppress intermediate selection events during projection. After validation, clean up old preview, project selected chart, and load the exact preview stopped. Only successful stopped load publishes the stage record and controller's Prepared state; projection/load failure resumes ordinary delayed primary-chart preview without preparation. Rejected requests leave the existing preparation alone.
- Ordinary delayed playback starts only in ordinary mode. Prepared/Playing/Failed never auto-start or fall back after delay/stop. Explicit start preserves idempotency and current error messages/result tuples, loops at existing preview volume, counts only actual playback time (negative delta clamps), reports failure on unexpected stop and retains stage-owned identity for telemetry. Clear both record and playback state on cancel/eligible activation or applicable row/difficulty change. Cancel with no prepared record preserves ordinary preview; transition eligibility is checked before cleanup so blocked activation is retryable. Stage composes telemetry from its identity and controller's state/elapsed facts; preserve relative identity and current speed/difficulty semantics.
- Preserve managed preview sound reference ownership, existing best-effort failure handling, instance replacement/stop/dispose ordering and repeat cleanup. Navigation SFX stays stage-owned. Verify recorder RPC callers before moving methods.

## B. Passive library intake — the stage drives reconciliation

Current seams: fields 129–138; initialization/subscription (804–914); initializer/publication/reconciliation (957–1051); stable chart/root eligibility and empty-state helpers (1607–1843). Use SongLibrary.GetLibrarySnapshot(), IsInitialized and SongLibraryPublished, not SongManager shims.

- Intake owns the event handler and scope's Latest<long> reporter. Subscribe(scope, onSignal) binds the stage's ApplyPendingLibraryPublication handler to **that activation's reporter**; publisher only reports a version. Unsubscribe idempotently against the actual subscribed library; no scope means no subscription. Retire scope before unsubscribe and UI/audio disposal. The stage owns initialization orchestration and readiness-related modal/placeholder effects, including posting ApplyInitializedLibrarySnapshot into the existing scope; no intake-driven UI callback chain.
- Passive operations (names illustrative): TryGetNewer(signal) fetches the current coherent library snapshot on drain and returns it only if max(signal, snapshot.Version) exceeds committed version; initializer path also accepts the initial snapshot when no snapshot has been installed (including version zero). Do not capture a worker-side snapshot or advance the marker at fetch. Install(snapshot) assigns applied snapshot/index/empty classification; Commit(version) advances the acknowledgment only after successful UI reconciliation; Filter(rows) returns the eligible projection. Initialization readiness is set on success/failure by the stage; keep prior valid snapshot on failure, otherwise clear placeholder and unblock search.
- Keep **one linear ReconcileLibrarySnapshot in the stage**: capture stable navigation paths and previous selection identity + begin tab refresh consumption; intake.Install(snapshot); stage sets roots and preview panel active paths; restore navigation and rebuild search filter; project active tab and restore retained selection or clear removed selection/preview/status; update breadcrumb/folder hint; complete tab refresh consumption; intake.Commit(snapshot.Version). The publication handler commits the max of signal/fetched version after successful reconciliation (preserve existing ordering), never before. Initial entry and deferred initialization reuse the stage method. No UI effects on publisher thread, no duplicate authoritative snapshot in stage/tabs.
- Extract existing pure root/score identity, path normalization and empty-classification logic with the intake (internal static functions; a separate static SongLibraryEligibility file is optional only if it improves clarity, not a fourth stateful owner). Test using plain snapshots/nodes; keep browse-specific stable box/selection restoration in stage. Match active-root membership and currently published song/chart identity; exclude missing chart rows using ExistingCharts. Distinguish no snapshot (existing permissive projection seam) from explicit empty roots. Preserve no-active-roots/no-supported-charts/has-songs distinctions and display copy. Keep cached rows intact so re-publication can restore previously hidden ones. Test actual stage reconciliation separately with no fake callback graph.

## C. Tabs and bookmark writes

Current seams: fields 67–126; active-tab projection/refresh (2183–2254); tab bar and recent label helpers (2838–2882); SwitchToTab, loads, bookmark writes (3428–3760). Reuse SongSelectionTab.Next(), BookmarkStateReconciler, and SongQueryService.GetRecentlyPlayedNodesAsync(20), GetBookmarkedNodesAsync(), SetBookmarkAsync().

- Stage still routes Tab/B, pad double hits, overlay suppression, sound feedback, focus reset and visible-list/UI changes. Tabs owns active tab, reset-to-All, warm loads and projected flat rows plus distinct empty/error states. Stage applies rows to SongListDisplay and owns All's hierarchical/filtered projection. Use intake's final eligibility/snapshot accessors directly via narrow seams; do not destructively trim cache or duplicate filters. Preserve labels/order, empty/error text and tab cycle.
- **One BeginLoad(tab) path for Recent and Bookmarks**, using existing HPA-799 Run/RunAsync. Choose existing query/loader for the tab; execute DB access off update thread, materialize independent result collections, and apply success/error only via drain. Give each flat tab its own request generation; increment when requesting a load, reject older success AND failure, independent of the other tab. Bookmark toggles also invalidate in-flight Bookmark loads, not Recent loads. If a bookmark tab switch waits for writes, bind deferred load to the captured scope and ensure superseded requests cannot replace a newer request; keep the existing wait-then-query semantics. Retirement drops all old UI callbacks. This intentionally fixes the documented stale Recent result/error race at 3467–3497; no other tab behavior change. Preserve refresh consumption version/dirty protocol and reset stale flags before initial projection.
- Move the **entire** bookmark write path together. Per-song writes chain after prior writes even if prior failed; last intent wins. Switching into Bookmarks waits for in-flight writes and posts its load to the captured scope. Persistence survives navigation; only origin-scope UI rollback drops. Keep pending-write dictionary, per-song toggle generation and revert gate across activation resets. At final stage disposal retain bounded five-second wait/log before game disposes library/database.
- Preserve persisted-ID preference, zero-ID selected-node-only flip, immediate cross-representation stars, removal on unbookmark, duplicate SET.def reconciliation and version-guarded optimistic shared-root update. Current failed write rolls back applied and latest root trees plus Recent/Bookmark caches, reloading a wrongly removed row when appropriate. If origin scope retired, drop UI revert but still do generation-checked shared-library revert under the same gate as optimistic shared updates. Capture library instance; no callbacks access new activation UI. Do not simplify existing concurrency guarantees.
