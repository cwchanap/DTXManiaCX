## Objective

The current `DTXMania.Game/Lib/Stage/SongSelectionStage.cs` is 4,077 lines, mixing preview audio, tab query/persistence state, library publication intake, UI projection, input and transitions. Extract three cohesive concrete owners under `Lib/Stage/SongSelection/`. The stage remains the UI coordinator and owns lifecycle, layout, input, browse navigation, search/filter UI, selection/difficulty, prepared-chart resolution/projection and transitions.

Preserve live behavior and visuals, with narrow correctness fixes at extracted seams: stale Recent results/errors cannot overwrite newer requests; deferred Bookmark refreshes cannot be lost or read before later pending writes settle; removing the selected prepared chart clears its stale preparation together with playback. Removing verified dead BGM code is not a live behavior change.

One PR (this draft), at most three engineer days including test migration and acceptance. Implement as reviewable commits: dead BGM deletion, preview, intake, tabs. No DI container, generic framework, new service interfaces, event bus, compatibility layer, new assets, database/schema changes, SQL query rewrites, audio timing changes, or general Song Select redesign. Do not reopen HPA-799 or HPA-801. Use the current .NET 10 toolchain and unified `DTXMania.Test.csproj`.

## Ownership and dependency direction

| Owner (concrete internal class) | Owns | Collaborators |
| --- | --- | --- |
| `SongSelectionPreviewController` | Preview sound/instance refs, ordinary delayed start, stopped/explicit prepared playback, playback state and elapsed time | Lazy resource-manager accessor, logger, explicit audio path |
| `SongSelectionLibraryIntake` | Publication subscription, applied snapshot/index, version marker, active roots, flat-list eligibility and library-empty classification | Game-owned SongLibrary, existing activation scope; stage supplies publication signal handler |
| `SongSelectionTabs` | Active tab, recent/bookmark caches and error/empty projection state, refresh generation, unified generation-guarded loads, separate deferred Bookmark request ID, optimistic bookmark mutation and ordered persistence/rollback | Game-owned SongLibrary.Queries, intake's final snapshot/filter accessors, logger, explicit activation scope |
| `SongSelectionStage` | UI, input, navigation stack, selection/difficulty, filter criteria/view, prepared selection record/projecting guard, initialization readiness, reconciliation sequence, drawing, lifecycle, transitions | Three concrete collaborators and existing game services |

Keep the collaborators stage-instance lifetime (particularly tab writes), with explicit activation resets and subscription lifecycle as needed; do not recreate them per frame or expose fields for tests. Resolve resources/library lazily where current construction permits uninitialized game stubs: no DB initialization or filesystem work in a constructor. Keep one game-owned SongLibrary; no new singleton. Use direct concrete constructor parameters and narrowly scoped delegates for actual I/O/test seams. Pass the actual activation scope when scheduling, not a later lookup of BackgroundWork. The stage drives reconciliation in one linear method; no stage passed to helpers, nested orchestration callbacks or cyclic dependencies. Implement intake before tabs so final filter/snapshot accessors exist when tabs is extracted.

## A. Preview and prepared recording

Current seams: fields 159–162, 201–219; PrepareVideoChart / StartPreparedPreview / CancelPreparedChart / ActivatePreparedChart (1341–1496); preview timers/ownership (3118–3379); selection/difficulty handlers (1851, 1957); telemetry (3980–3996).

- Move preview refs, delay timer, sound load/create/stop/release, prepared playback state (None/Prepared/Playing/Failed) and elapsed ms into the preview controller. It accepts audio paths, not SongListNode/SongChart or a browse-selection record. Construct with Func<IResourceManager?> getResourceManager and ILogger, using the current resource manager only when loading (including headless constructor fixtures); no mutable resource bind/unbind lifecycle. Its small surface is LoadDelayed(path), LoadStopped(path), StartPrepared(), Stop(), Update(delta), PreparedState and PlayedMs (names illustrative). The stage retains the PreparedChartSelection(Node, Chart, DifficultyIndex, TelemetryIdentity) record, exact-chart resolution, path/eligibility validation, browse projection and guard, ordinary primary-chart path selection, recorder-facing methods, input/transition policy and navigation SFX. Do not duplicate playback facts in stage or selection facts in controller.
- Stage validates the requested exact chart, preview declaration and file existence **before** disturbing an existing preview/preparation; suppress intermediate selection events during projection. After validation, clean up old preview, project selected chart, and load the exact preview stopped. Only successful stopped load publishes the stage record and controller's Prepared state; projection/load failure resumes ordinary delayed primary-chart preview without preparation. Rejected requests leave the existing preparation alone.
- Ordinary delayed playback starts only in ordinary mode. Prepared/Playing/Failed never auto-start or fall back after delay/stop. Explicit start preserves idempotency and current error messages/result tuples, loops at existing preview volume, counts only actual playback time (negative delta clamps), reports failure on unexpected stop and retains stage-owned identity for telemetry. **Stop contract:** Stop releases the current preview instance/reference, clears the ordinary delay and resets playback state to None and elapsed ms to zero, idempotently. The stage's ClearPreparedPreviewState is the sole cleanup path for an owned preparation: call Stop and clear its record in the same synchronous stage operation. Route ClearRemovedSelectionPresentation (1593–1605) through ClearPreparedPreviewState rather than audio-only stop, even if no prepared record exists (ordinary preview must still stop). Other direct Stop calls are allowed only when no prepared record exists; audit every existing StopCurrentPreview call. Clear both record and playback state on cancel/eligible activation, removal, deactivation or applicable row/difficulty change. Assert no non-null record paired with None, and no prepared/playing/failed state without its record at the end of a stage operation. An unexpected playback stop remains Failed with identity, not an explicit Stop/reset. Cancel with no prepared record preserves ordinary preview; transition eligibility is checked before cleanup so blocked activation is retryable. Stage composes telemetry from its identity and controller's state/elapsed facts; preserve relative identity and current speed/difficulty semantics.
- Preserve managed preview sound reference ownership, existing best-effort failure handling, instance replacement/stop/dispose ordering and repeat cleanup. Navigation SFX stays stage-owned. Verify recorder RPC callers before moving methods.

## B. Passive library intake — the stage drives reconciliation

Current seams: fields 129–138; initialization/subscription (804–914); initializer/publication/reconciliation (957–1051); stable chart/root eligibility and empty-state helpers (1607–1843). Use SongLibrary.GetLibrarySnapshot(), IsInitialized and SongLibraryPublished, not SongManager shims.

- Intake owns the event handler and scope's Latest<long> reporter. Subscribe(scope, onSignal) binds the stage's ApplyPendingLibraryPublication handler to **that activation's reporter**; publisher only reports a version. Unsubscribe idempotently against the actual subscribed library; no scope means no subscription. Retire scope before unsubscribe and UI/audio disposal. The stage owns initialization orchestration and readiness-related modal/placeholder effects, including posting ApplyInitializedLibrarySnapshot into the existing scope; no intake-driven UI callback chain.
- Passive operations (names illustrative): TryGetNewer(signal) fetches the current coherent library snapshot on drain and returns it only if max(signal, snapshot.Version) exceeds committed version; initializer path also accepts the initial snapshot when no snapshot has been installed (including version zero). Do not capture a worker-side snapshot or advance the marker at fetch. Install(snapshot) assigns applied snapshot/index/empty classification; Commit(version) advances the acknowledgment only after successful UI reconciliation; Filter(rows) returns the eligible projection. Keep _libraryInitializationCompleted exclusively on SongSelectionStage: only its search modal consumes readiness. Stage sets it on initializer success/failure and reset, and unblocks the modal; keep prior valid snapshot on failure, otherwise clear placeholder. Delete ApplyLibrarySnapshot (849–852, reflection-only) instead of extracting it; migrate its tests to Install/Commit or real stage reconciliation, preserving behavior.
- Keep **one linear ReconcileLibrarySnapshot in the stage**: capture stable navigation paths and previous selection identity + begin tab refresh consumption; intake.Install(snapshot); stage sets roots and preview panel active paths; restore navigation and rebuild search filter; project active tab and restore retained selection or clear removed selection/preview/status; update breadcrumb/folder hint; complete tab refresh consumption; intake.Commit(snapshot.Version). The publication handler commits the max of signal/fetched version after successful reconciliation (preserve existing ordering), never before. Initial entry and deferred initialization reuse the stage method. No UI effects on publisher thread, no duplicate authoritative snapshot in stage/tabs.
- Extract existing pure root/score identity, path normalization and empty-classification logic with the intake (internal static functions; a separate static SongLibraryEligibility file is optional only if it improves clarity, not a fourth stateful owner). Test using plain snapshots/nodes; keep browse-specific stable box/selection restoration in stage. Match active-root membership and currently published song/chart identity; exclude missing chart rows using ExistingCharts. Distinguish no snapshot (existing permissive projection seam) from explicit empty roots. Preserve no-active-roots/no-supported-charts/has-songs distinctions and display copy. Keep cached rows intact so re-publication can restore previously hidden ones. Test actual stage reconciliation separately with no fake callback graph.

## C. Tabs and bookmark writes

Current seams: fields 67–126; active-tab projection/refresh (2183–2254); tab bar and recent label helpers (2838–2882); SwitchToTab, loads, bookmark writes (3428–3760). Reuse SongSelectionTab.Next(), BookmarkStateReconciler, and SongQueryService.GetRecentlyPlayedNodesAsync(20), GetBookmarkedNodesAsync(), SetBookmarkAsync().

- Stage still routes Tab/B, pad double hits, overlay suppression, sound feedback, focus reset and visible-list/UI changes. Tabs owns active tab, reset-to-All, warm loads and projected flat rows plus distinct empty/error states. Stage applies rows to SongListDisplay and owns All's hierarchical/filtered projection. Use intake's final eligibility/snapshot accessors directly via narrow seams; do not destructively trim cache or duplicate filters. Preserve labels/order, empty/error text and tab cycle.
- **One BeginLoad(tab) query path for Recent and Bookmarks**, using existing HPA-799 Run/RunAsync. Choose existing query/loader for the tab; execute DB access off update thread, materialize independent result collections, and apply success/error only via drain. Give each flat tab its own query generation: invalidate previous queries when requesting a newer load and capture the current/new generation at actual query launch; reject older success AND failure. Bookmark toggles invalidate in-flight Bookmark queries only, never Recent queries. This fixes the documented stale Recent race at 3467–3497. Preserve refresh consumption version/dirty protocol and reset stale flags before initial projection.
- **Deferred Bookmark requests are not query generations.** Keep a separate monotonic _deferredBookmarksRequestId for refresh intent, incremented on a new Bookmark refresh request (switch into Bookmarks; use the same entry path for warm/rollback refresh to avoid bypassing an outstanding wait). On the update thread capture the request ID and originating scope; wait asynchronously for the currently incomplete pending-write tasks, including writes to different songs. Continuation only posts back to that scope even on write fault/cancellation. On drain, drop if request ID is superseded; otherwise re-read pending writes. If any newer incomplete writes exist, wait again with the **same** request ID and scope; otherwise start the actual BeginLoad(Bookmarks) on the update thread with a fresh query generation. No spin/poll loop on a worker or update thread, no new queue. A toggle increments only Bookmark query generation, **not** the deferred request ID, so it cannot cancel the owed reload. A newer explicit Bookmark refresh supersedes the older deferred request. If a later toggle invalidates an already-running query, retain the same outstanding refresh intent and re-enter the wait/requery path on stale completion only if its request ID is still current; do not apply stale rows/errors, and do not retry if a newer request has taken over. Retirement drops all queued load work; never cancel durable writes.
- Regression: W1 bookmarks A → switch to Bookmarks (deferred) → W2 unbookmarks cached B → settle W1 and drain while W2 is pending (no query) → settle W2 and drain (one current query) → A present/B absent after drain. Also cover new explicit refresh superseding older wait, scope retirement, faulted/canceled write settling rather than hanging, and toggle invalidation of an already-started query. Use deterministic TCS gates/real scope, not sleeps.
- Move the **entire** bookmark write path together. Per-song writes chain after prior writes even if prior failed; last intent wins. Switching into Bookmarks waits for in-flight writes and posts its load to the captured scope. Persistence survives navigation; if the origin scope retires with no current activation, UI rollback drops, whereas if a newer activation is already current at fault time, the same version-guarded cache rollback forwards there. Keep pending-write dictionary, per-song toggle generation and revert gate across activation resets. At final stage disposal retain bounded five-second wait/log before game disposes library/database.
- Preserve persisted-ID preference, zero-ID selected-node-only flip, immediate cross-representation stars, removal on unbookmark, duplicate SET.def reconciliation and version-guarded optimistic shared-root update. Current failed write rolls back applied and latest root trees plus Recent/Bookmark caches, reloading a wrongly removed row when appropriate. If origin scope retired, always perform the generation-checked shared-library and gate-owned in-memory state revert under the same gate as optimistic shared updates, and forward the same version-guarded cache rollback (`ApplyBookmarkRevertCore`) to the activation current at fault time so re-entered Recent/Bookmarks views do not retain stale optimistic flags; drop UI revert only when no newer activation is current. Capture library instance; callbacks remain version-guarded by toggle generation. Do not simplify existing concurrency guarantees. Delete reflection-only ApplyBookmarkRevert (3720–3721); retain actual ApplyBookmarkRevertCore behavior and migrate the stale-revert test to a real queued rollback path.
