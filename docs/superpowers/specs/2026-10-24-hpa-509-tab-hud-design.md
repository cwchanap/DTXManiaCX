# HPA-509 — Tab-mode HUD design

**Linear:** https://linear.app/cwchanap/issue/HPA-509/tab-mode-tab-mode-hud-layout  
**Parent:** HPA-394 · **Dependency:** HPA-411 (merged as #202)  
**Delivery:** one implementation PR, <=3 engineer days. This document is design-only pending review.

## Goal

Make opt-in Tab mode usable with its own 1280×720 HUD, matching approved mockup C while keeping the existing scrolling notation, judgement, scoring, audio and Lanes presentation untouched.

The approved behavior is: title/artist top-left, score top-right, combo and judgement/fast-slow above the fixed x=220 hit line, horizontal LIFE just above the notation, 10 key labels with hit flash, progress with elapsed/total directly below notation, and a bottom row of judgement/skill stats. No pads, vertical progress meter or skill graph in Tab.

## Verified implementation baseline (main after #202)

- `PerformanceStage.OnDraw` already switches on effective Tab via the retained, ready `_notationStrip != null`; Lanes are the fallback. The switch also suppresses falling-note overlays and lane hit effects.
- `DrawUIElements` currently suppresses the four obstructing legacy draws in Tab: `DrawSkillPanel`, `DrawProgressBar`, `_skillPanelDisplay.Draw`, `_skillMeterDisplay.Draw`. It **still** draws the old gauge, score and combo at Lanes positions.
- **Unaddressed lane transients in current main:** `OnJudgementMade` unconditionally calls `_spriteJudgementTextPopupManager.SpawnPopup(e)` and can call `_hitTimingFeedbackDisplay.Spawn(e)`; `DrawJudgementTexts` unconditionally draws sprite, font fallback and timing displays. HPA-509 gates the **two spawn calls** in effective Tab, leaving existing Lanes draw methods unchanged. The font fallback is only spawned from the sprite manager; the effective display mode is fixed before input, so no legacy transient exists to draw in Tab.
- `PerformanceUILayout.NotationStrip` fixes strip x=0..1280, y=290..580, key mask x=0..195, hit line x=220, and the BackToFront layer depths. These are **not** to be moved by this ticket.
- `SkillPanelDisplay` already maintains Perfect/Great/Good/Poor/Miss/MaxCombo counts and the current achievement/skill display value via existing manager events; `ScoreDisplay`, `ComboDisplay`, `_currentGaugeValue` and `_currentProgressValue` already have the live values. `Poor` should be presented as `OK` in the mockup row, with no judgement rule change.
- `OnJudgementMade` owns the single event fan-out to existing managers and popup spawns. `OnLaneHitForPadFeedback` receives manual lane indices (0–9), and `JudgementEvent.Lane` carries the same identity but **not a channel**. `NotationStripLayout.GetKeyColumnLabels` currently returns text/y keyed by primary DTX channel; `DTXChartParser.ChannelToLaneMap` is the canonical channel→lane mapping and is currently private. This ticket may expose a narrow `internal static TryGetLane(channel, out lane)` lookup on the parser to add `Lane` to each `NotationStripLabelAnchor`; it must not duplicate mapping tables or make the dictionary mutable/public. Physical LP (lane 2) flashes **LP** on a 0x1C left-bass judgement, even though 0x1C is engraved at the BD staff position.

## Layout contract

All Tab-specific bounds, font sizes, colors, paddings, text anchors and depth values belong in a nested `PerformanceUILayout.TabHud` class; Lanes constants must not be modified. Initial 1280×720 safe regions:

| Region | Bounds / placement | Contents |
| --- | --- | --- |
| Header | x=20..1260, y=8..90 | Clamped/ellipsized title + artist left, score digits right |
| Hit feedback | around x=220, y=125..250 | Combo above the hit marker; transient judgement plus fast/slow. Keep out of score/header |
| LIFE | x=195..1260, y=260..283 | LIFE label in left column and horizontal gauge; below feedback and above strip |
| Notation | existing x=0..1280, y=290..580 | **Unchanged** strip, marker and mask; left key labels flash on matching hit |
| Progress | x=195..1260, y=586..617 | Thin horizontal progress fill and elapsed/total at left |
| Stats row | x=16..1264, y=628..704 | Compact tiles: Perfect, Great, Good, OK (Poor), Miss, Max Combo, Fast/Slow, Achievement %, Skill |

These are starting regions rather than a pixel-perfect assertion for dynamic font metrics. Use fixed virtual-space coordinates, legible 1280×720 rendering and bounded text; do not introduce resolution-specific UI frameworks, new navigation or responsive modes. Do not cover hit marker, approaching notes, key column or BGA with an old Lanes overlay.

## Design decision: one presentation owner, existing gameplay owners

Implement a small `TabHudDisplay` (or equivalent single renderer) for Tab drawing/short-lived feedback only. It takes a read-only snapshot of values from the existing stage/managers; it must not own or recalculate the score, combo, life, overall skill, hit windows, note judgements or logical song clock. Build fonts/pixel primitive resources once, not per frame. The stage decides which UI to draw using a single readiness flag (`_notationStrip != null && _tabHudDisplay.IsReady`) — a HUD whose resources failed to load falls back to the full Lanes display rather than drawing nothing — and disposes the Tab HUD with other resources.

- Preserve existing score/combo **updates** and their Lanes sprite rendering paths; suppress their legacy position draws in Tab. **Use the Tab HUD managed font for both score (top-right) and combo (above x=220)**, reading `ScoreDisplay.Score` and `ComboDisplay.Combo`. Legacy combo digit glyphs are approximately 160px tall plus a 162px-offset label, too large for the ~160px hit-feedback region, and the score sprites are positioned for Lanes. Do not try to relocate either sprite renderer.
- Keep `SkillPanelDisplay.ProcessJudgement` as owner of cumulative judgement counts. **Add `FastCount` and `SlowCount` there**; no cumulative counters currently exist. For successful judged hits only (exclude Miss), classify `e.DeltaMs` with the existing `PerformanceUILayout.HitTimingFeedback.ProjectDelta` signed-millisecond convention: negative = Fast, positive = Slow, zero = neither. Use the rounded projection so sub-millisecond values rendered as 0 are neutral. Do **not** create a second per-note judgement map or change judgement outcomes, scoring or skill calculations.
- Use existing song metadata and `TextHelper.TruncateToWidth` for bounded title/artist, and `_songTimer.GetCurrentMs(_currentGameTime)`, `_parsedChart.DurationMs` and the already-clamped `_currentProgressValue` for progress/time. Format time using standard `m:ss` TimeSpan formatting consistent with Song Select; do not introduce a second time formatter/parser or progress-clamping path. For the two distinct stats tiles, **Achievement % = `_skillPanelDisplay.Skill`**, and **Skill = `SongScore.CalculateGameSkill(achievement, chart.DrumLevel, chart.DrumLevelDec)`** using the same selected chart values already used by `SkillPanelDisplay`. Do not introduce a new skill formula.
- **Decision: one Tab popup slot, newest judgement wins.** `TabHudDisplay` holds **one `JudgementTextPopup?`**, constructed with the existing `OnJudgementMade(e)` judgement word at the fixed x≈220 position; each new event replaces the previous popup immediately, including chords and rapid notes. Reuse `JudgementTextPopup`'s existing fade/rise/expiry behavior, **not** a new timer/queue/stack or lane-positioned popup manager. Permit only a visibility change to the existing `JudgementTextPopupManager.JudgementTexts`/`JudgementColors` mapping (private → internal, no mutation) to reuse wording/colors without copying. Do not otherwise modify either legacy popup manager's runtime behavior. In effective Tab (the HUD-readiness flag above), skip **only** the existing `_spriteJudgementTextPopupManager.SpawnPopup(e)` and `_hitTimingFeedbackDisplay.Spawn(e)` calls; the existing `DrawJudgementTexts` draw calls remain unchanged and have no Tab transients to draw. Preserve existing Lanes spawning, fallback and draws. The Tab transient is short-lived presentation state, not a per-note result store.
- **Per-hit Fast/Slow visibility:** compute the existing Lanes visibility predicate once in `OnJudgementMade`: `_visualGates.ShowHitTimingFeedback && e.IsHit() && !FrozenAutoPlayLanes.Contains(e.Lane)`. Forward it to Tab HUD transient text; the current Lanes `HitTimingFeedbackDisplay.Spawn` still uses the same predicate. The permanent Fast/Slow **count tiles** remain always visible, including in AutoPlay (which contributes rounded-zero offsets and therefore increments neither). Do not introduce a new preference or AutoPlay filter on counters.
- **Miss visibility under chords/fast passages:** the strip masks x<195; at normal speed a >200ms-late Miss head is hidden. The single popup is intentionally newest-wins, so **also flash the affected lane's key label in Miss red** on every Miss to preserve instrument identity when the popup is replaced quickly. Successful judged hits/AutoPlay also flash their lane; manual input flashes immediately even without a note. Maintain just **one per-lane timer+color slot**, refreshed/overwritten by events, never enqueue a second flash. No notehead tint/fade/source-note anchoring in this PR.
- **Label identity contract:** extend `NotationStripLabelAnchor` with `Lane`, computed for each existing `LabelDisplayOrder` primary channel via the narrow `DTXChartParser.TryGetLane` lookup. All ten primary labels must map one-to-one to lane indices 0–9 (including BD→5, LP→2); variant channels do not create duplicate labels. This resolves the BD/DB spelling difference and 0x1C left-bass ambiguity. Use the existing label anchor y/position rather than sorting by y or matching names; no new lane mapping table or second autoplay tracker.
- The life and progress fills are simple textured/drawn rectangles using existing white-pixel/fallback conventions. The skill-meter graph stays suppressed. Pause/danger and gameplay state overlays retain existing semantics; placement conflicts should be checked on a real screenshot.

## Render and ownership boundaries

- Keep `PerformanceStage.OnDraw`'s existing base, overlay, UI and additive passes. **Only key flashes draw in the base BackToFront batch**, via `TabHudDisplay.DrawKeyFlashes(spriteBatch)` directly after `DrawNotationStrip()`, with `PerformanceUILayout.TabHud.DepthKeyFlash = 0.35f` **between** the notation key-mask depth 0.40 and label depth 0.30; use cached white-pixel primitive/alpha so labels remain legible. All other Tab HUD content draws in the subsequent UI pass. Depth ordering does not cross separate SpriteBatch batches; a filled flash in the UI pass would cover the label. Respect explicit font/sprite depths rather than defaulting to 0.
- Lanes code path and positioning remain **bit-for-bit equivalent in intent**. If optional Tab HUD font/primitive acquisition fails, **log and skip that HUD draw**; do not add a second/minimal HUD mode or modify the effective display selector. The existing **notation renderer failure** already falls back Tab → Lanes via `_notationStrip == null`, without rewriting the saved `NoteDisplayStyle`. No new scene, config switch, saved-state schema or telemetry mode field.
- Retain existing `_notationStrip` readiness and fallback policy, stage lifecycle/resource cleanup and shared managers. Only the narrow parser channel→lane lookup and label-anchor lane field are permitted; otherwise no production changes to `NotationChart`, `NotationStripRenderer` timing/engraving, `JudgementManager`, parsing behavior, audio or note input routing.

## Acceptance and evidence

1. Tab at actual 1280×720: all regions fit, no clipped title/stats, no overlap with the hit marker or notation, BGA remains behind the strip; capture a **real GPU screenshot** on the PR.
2. All ten key labels map one-to-one to lanes 0–9 and remain clearly legible above correctly layered flashes; 0x1C left bass / lane 2 highlights LP, not BD. Manual input, AutoPlay and Miss update the correct label; Miss turns it red even when a newer popup replaces its text. An AutoPlay run reaches Result.
3. Counts, score, **distinct achievement and level-weighted game skill**, LIFE, combo, progress and elapsed/total reflect existing values; unstarted/zero-duration charts render safely. Per-hit Fast/Slow text obeys the existing `_visualGates.ShowHitTimingFeedback && e.IsHit() && !FrozenAutoPlayLanes.Contains(e.Lane)` opt-in rule in both modes. Cumulative Fast/Slow tiles are **not** gated and exclude Miss and rounded-zero deltas.
4. Switching back to Lanes is visually unchanged, including legacy score/combo/gauge, skill panel/meter, progress and pad feedback. Invalid Tab renderer still falls back to Lanes.
5. Add focused **lane-to-label one-to-one mapping** and layout-geometry tests, per-lane flash replacement/color/decay tests (including Miss), Fast/Slow signed-count tests, and existing-category Tab AutoPlay verification. Test effective Tab/Lanes **spawn** suppression through the established `PerformanceStageDeterministicTests` reflection pattern; do not unit-test GPU-only `[ExcludeFromCodeCoverage]` draw paths. Reuse existing `JudgementTextPopup`, `TextHelper` and progress tests rather than duplicating their fade/expiry, truncation or clamping coverage. GPU pixels require a real screenshot.

## Explicit exclusions / follow-up gate

No notehead tint/fade, moving the key mask/marker, new custom art/SFX, new chart feedback store, editor work, UI framework migration, arbitrary screen-size redesign, CI pipeline changes, changes to parsing **behavior**, or refactoring the Lanes HUD. A tiny read-only parser mapping accessor and internal presentation-text visibility change are the only cross-component API surface additions. If later playtesting justifies visible-on-note resolution effects, raise a separate follow-up ticket; don't expand HPA-509 beyond three engineer days.
